课程通览：Claude Code 企业级老项目改造实战

基本信息

  • 模块数：11（含热点速递、开篇词、结束语等非编号模块）
  • 总讲数：37（编号讲课 01-33 + 热点速递 + 开篇词 + 结束语 + 结课测试）
  • 总时长：约 510 分钟（含 5 节实操视频课，约 165 分钟）
  • 讲师：Robert（自称"多年接老项目"的资深工程师，个人经历导向，无公开履历背书）
  • 课程定位：以"AI 协作心智 + 工具地图 + 判断力框架"为底座，用 Claude Code 对老项目做"理解→约束→验证"的可信改造，全程以 Spring AI Alibaba Admin 为实战载体，附带 Hermes Agent 二次开发与开源贡献两个变体场景

Adler 两问（检视阅读阶段必答）

  • Q1: 这门课整体讲了什么？ 一门关于"怎么用 Claude Code 改造跑了多年的老项目"的实操方法论课。课程主张：老项目改造的本质是"理解 + 开发"两件事，AI 没有推翻这条链路，只改变了每一步里人和 AI 的分工。方法论骨架是"九步链路（01）→ 三档分工（02）→ 三层控制：理解/约束/验证（03）"，之后用"了解项目（06-12）→ 运行测试建护栏（13-16）→ 需求改造（17-23）→ 二次开发（24-29）→ 开源贡献（30-32）"五个真实场景把骨架跑三遍，最后以"改造 SOP"（33）收束。
  • Q2: 作者想要解决什么问题？解决了多少？ 解决"AI 改老代码为什么效果差"的问题，答案分两层：①方法层——理解、约束、验证三层控制 + 一整套可复制的提示词工作流（需求六维、方案七步、Characterization Test、CLAUDE.md/SKILL 资产化），把改造质量稳定在 80 分以上；②认知层——"AI 是加速不是兜底""工作量下来 ≠ 思考量下来"。已解决：理解项目（docs 五份资产）、跑通环境、补测试建 CI、拆需求拆方案、执行改造的完整闭环。未解决：方法依赖讲师个人经验，缺少可独立验证的数据支撑（全课 18 条量化声明几乎全部无法独立验证）；"改造前点产品"等兜底动作依赖个人纪律。回避：未讨论 Claude Code 的价格/合规/公司禁止场景下的替代方案细节；未提供真实生产项目（非教学演示项目）的长期验证结果。

整体印象

  • 课程主线："理解+开发"是本质，AI 只改变分工不改变链路；用"理解→约束→验证"三层骨架 + 一整套可复制提示词，把老项目改造稳定在 80 分以上。
  • 最大亮点：①诚实——20 讲"翻车复盘"和 22 讲"三个失败模式"主动展示失败，这在 AI 编程课程中极稀缺；②可操作性——核心方法论每讲都有可直接复制的提示词；③资产化闭环——docs 五份资产 → CLAUDE.md → SKILL → 改造后回写，形成"活资产"。
  • 明显水份：①实操课 5 节（12/16/21/29/32）大量重复已讲提示词；②09 讲 22K 字大半是样例文档；③05 讲业界数据大量无法验证；④讲师经验型量化声明（70%/80%/20 分钟/99%）贯穿全课，无独立来源。
  • 独特之处："AI 是加速，不是兜底"的清醒定位，与主流"AI 编程神效"叙事形成反差；"人补 AI 弱的 30%""工作量下来≠思考量下来"等反直觉判断。
  • 形式/内容判断：这门课主要在"教思维方式+可复制工作流"（方法论占比高），而非堆砌事实知识。但思维方式的支撑证据偏个人经验，缺少可独立验证的量化背书。批判性缺口：全课基本没有讨论 Claude Code 的失败成本（算力/额度/安全隐患），也没有与"不用 AI 的传统改造"做对照实验。
