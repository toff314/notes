# 第 15 讲 · 用 Characterization Test 锁住行为（🥇 4.3）

- **结论**：AI 补改造前兜底测试的最大风险不是漏测，而是按业务直觉写"应该"断言，把历史包袱当 bug 锁死。对策：提示词强制 AI 先跑代码记录实际行为，再转成断言。
- **证据**：方法引自 Michael Feathers《Working Effectively with Legacy Code》（2004）✅；补测试四档优先级：改造路径 Characterization > 核心链路集成 > 复杂逻辑单元 > 简单 CRUD 可不补；每批只补 1-3 个，review 后放行。"30 分钟 CI 换上千次检查"为讲师估算 ❓。
- **与其他讲的关系**：验证层核心，上承 13/14 摸底，下启 19 改造后对比；呼应 05 讲"验证债"。
- **我的批判**：未讨论"测试锁死历史 bug 后未来修复的摩擦成本"，也没给断言覆盖度量化标准；但"AI 写'应该'断言"的偏差识别是大多数 AI 测试教程没有的真洞察。
