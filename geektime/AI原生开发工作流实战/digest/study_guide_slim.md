# AI原生开发工作流实战 — 5 分钟速览

## 如果你只记住一件事
AI 原生开发的核心是"**规范驱动开发（SDD）**"：把"代码是真理"倒转为"**规范是真理**"，你从写代码的人变成写规范、编排工作流、治理质量的人。

## 3 个核心框架
1. **SDD 四阶段编译链**：spec.md（意图）→ plan.md（方案）→ tasks.md（任务）→ 代码，AI 扮演逐级"编译器"。
2. **渐进式披露**：Skill 只注入 description 索引、按需加载指令、深度加载脚本，让 AI 知识库无限扩展而上下文保持轻量。
3. **AI 协作框架全景**：项目级（团队共享，提交 Git）与用户级（个人专属）两层，组织 commands/skills/agents/hooks/settings。

## 5 个可操作方法
1. **坚持 TDD**：先让 AI 写失败测试并人工审查，再写实现——防止 AI"自洽幻觉"（代码和测试一起错）。
2. **Bug 归属二分**：意图偏差改 spec.md 重新生成；实现错误直接修代码——维护"意图的单一来源"。
3. **写 Skill 用共情式**：放弃 MUST/NEVER 恐吓，解释"为什么"，AI 才能在边缘场景做出正确变通。
4. **确定性剥离**：正则清洗、Git 提取等确定性逻辑写成脚本，让 LLM 只做意图理解，省 Token 更鲁棒。
5. **标准流程用 Command，探索任务用 Skill**：审查/提交追求确定性用 Slash Command，开放式任务才用自主发现的 Skill。

## 1 个反直觉观点
AI 时代更要坚持 TDD——不是因为 AI 写测试慢，而是因为让 AI"同时生成代码和测试"会产出**自洽但错误**的结果：测试全绿，功能却是错的。测试先行是唯一能让人类低成本验证"正确性"的锚点。

## 值不值得花时间？
**值**（但有取舍）——概念篇（02）和实战篇的 TDD 心法（19）是真正可迁移到任何 Coding Agent 的底层思想，值得精读；但约一半篇幅是 Claude Code 工具操作，会随版本快速贬值，快览即可。
