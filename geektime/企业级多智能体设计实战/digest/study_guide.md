## 核心知识地图（按主题重组，非原课程顺序）

### 主题一：从"面向过程"到"面向组织"
**一句话总结**：AI 应用开发的范式从写提示词（Prompt）→ 组上下文（Context）→ 造环境（Harness），控制权从"写内容"转向"造环境"。

**关键框架**：三代演进把 Agent 比作一匹马——Prompt 时代你是骑手（手把手拉缰绳），Context 时代你是教练（规划赛道），Harness 时代你是牧场主（建好围栏让马自己吃草）。

**可操作方法**：
1. 用 Bootstrap 预加载导航骨架（索引>全文），不塞全部内容（来源：第 19 讲）
2. 关键信息放上下文两头（利用 U 型注意力分布），中间精简（来源：第 18 讲）
3. 治理上下文用"加法+减法"双框架，只做加法必然 Context Rot（来源：第 18 讲）

**金句**：
> "大模型没有记忆。每一次 API 调用都是独立的……记忆的本质，就是一套构建 message list 的机制。" — 第 18 讲

### 主题二：数字员工团队的协作协议
**一句话总结**：Orchestrator 解决"怎么分工做事"，数字团队解决"做事的是谁"——从用完即抛的调度，升级到有 soul/skill/记忆的持久化员工。

**关键框架**：模块四的四机制递进——角色设计（三维隔离+NEVER 清单）→ 任务流转（共享工作区+邮箱三态机）→ 人类介入（甲方三件事）→ 自我进化（五步闭环）。

**可操作方法**：
1. 新增角色前用三维隔离判断法（记忆/技能/决策偏好），两个以上"是"才新建（来源：第 25 讲）
2. 邮箱用三态状态机（unread→in_progress→done）而非 read:bool，防 Agent 崩溃丢任务（来源：第 26 讲）
3. 人只和 Manager 沟通（单一接口原则），需求落文档才算数（来源：第 27 讲）
4. 复盘用 root_cause 枚举逼出分类思考，打破"下次注意移动端"式复述（来源：第 28 讲）

**金句**：
> "Orchestrator 是用完即抛的调度机制，Manager 是跨 session 积累经验的持久化团队成员。" — 第 25 讲

### 主题三：企业级加固——Prompt 是建议，Hook 是法律
**一句话总结**：可观测、可靠、安全三件事都必须放工程层，因为"模型是完全不可信的，让被监控对象自己报告监控数据，等于让考生自己批改试卷"。

**关键框架**：5+2 事件 Hook 骨架统一零散钩子，三策略（重试/循环检测/成本围栏）与三层安全（沙箱/权限网关/身份认证）作为插件挂载，改 yaml 不改代码。

**可操作方法**：
1. 循环检测用状态哈希去重（方向检测），max_iter 只作最后防线（来源：第 31 讲）
2. 成本围栏在 Hook 层用代码硬停止，不靠 Agent 自觉（来源：第 31 讲）
3. 权限用 Deny>Ask>Allow，新工具 Default-Deny（来源：第 32 讲）
4. 密钥在工具执行层注入，从不上 LLM 上下文（来源：第 32 讲）

**金句**：
> "安全不是给 Agent 下命令，是从能力上限制它能做什么。" — 第 32 讲

### 主题四：AI 项目失败的第一原因是选题，不是技术
**一句话总结**：四个独立机构报告交叉印证 AI 项目失败是行业级系统性失败，根因在"用正确的技术解决错误的问题"。

**关键框架**：需求挖掘三法（工作流审计/摩擦点溯源/规模增长映射）→ 四问过滤 → 5 维 25 分评估表 → 评测四环节 → 六层监控，构成从立项到上线到持续迭代的完整闭环。

**可操作方法**：
1. 用"量翻 10 倍是否需要 10 倍人"判断规模瓶颈（来源：第 34 讲）
2. 立项前必答 Q2"每周发生几次"，<10 次直接暂缓（来源：第 34 讲）
3. 评测汇总按维度细分而非只看整体通过率；用 pass^k 而非 pass@k 汇报（来源：第 36 讲）
4. 告警用消耗率（预算燃烧速度）而非原始阈值，噪声减 90%（来源：第 38 讲）

**金句**：
> "AI-enabled 是用 AI 把现有工作做得更快更好；AI-native 是问：有哪些有价值的事，因为人类的内在局限，从来没人完整做过？" — 第 34 讲
