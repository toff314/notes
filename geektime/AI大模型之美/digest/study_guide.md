## 核心知识地图（按主题重组，非原课程顺序）

### 主题一：两个原语——Completion 与 Embedding
**一句话总结**：全课所有应用都建立在这两个接口之上，理解它们就理解了「用接口替代训练」的根基。

**关键框架**：Completion 负责「生成」（续写、聊天、摘要、改写），Embedding 负责「检索」（把文本映射成向量，用余弦相似度度量语义距离）。传统 NLP 任务（分类、聚类、搜索）可被 Embedding 相似度「降维」成几行代码。

**可操作方法**：
1. 零样本分类：算「好评/差评」标签词的 embedding，与评论向量比余弦相似度，差值定正负（来源：第 02 讲）
2. 语义搜索：query 和文档都转向量，按相似度排序（来源：第 09 讲）

**金句**：
> "我们只需要简单利用大语言模型里面知道的「好评」和「差评」的概念信息，就能判断出它从未见过的评论到底是好评还是差评。" — 第 02 讲

### 主题二：第二大脑 / RAG——先搜索后提示
**一句话总结**：课程最核心的方法论，准确预见了后来主导行业的 RAG 范式。

**关键框架**：大模型有两类知识——「世界知识」（训练语料里已含的）和「上下文知识」（推理时临时提供的）。第二大脑模式 = 先把外部资料建索引 → 提问时先检索相关片段 → 再让 AI 基于检索结果回答。这解决了幻觉和时效性两大问题。

**可操作方法**：
1. 用 llama-index（或现代 RAG 框架）三行代码建索引、问答（来源：第 10 讲）
2. 树状摘要：分片小结→对小结再小结，突破单次 token 上限（来源：第 10 讲）
3. 冷启动推荐：无行为数据时用商品名语义相似度做推荐（来源：第 09 讲）

**金句**：
> "通过先将外部的资料库索引，然后每次提问的时候，先从资料库里通过搜索找到有相关性的材料，然后再通过 AI 的语义理解能力让 AI 基于搜索到的结果来回答问题。" — 第 10 讲

### 主题三：多步提示语 / 思维链
**一句话总结**：复杂任务不能「一股脑塞给 AI」，要拆成可逐步验证的中间步骤，这是 CoT 的前身。

**关键框架**：把任务拆成「解释代码 → 规划用例 → 生成代码 → 语法检查」四步，每步的输出作为下一步的上下文，最后加 AST 校验兜底。分步提示能让 AI 主动考虑边界条件（负数/None/超时），直接贴代码则只会得到覆盖不全的答案。

**可操作方法**：
1. 用 AST（ast.parse）校验 AI 生成代码的语法，失败则重新生成（来源：第 13 讲）
2. 生成测试用例后检查数量，太少则追加提示语让其补充边界用例（来源：第 13 讲）

**金句**：
> "如果我们只是直接把代码往 ChatGPT 里一贴，虽然也能生成测试用例，但是那些测试用例就比较欠考虑，不会涵盖各种边角的情况。" — 第 13 讲

### 主题四：工具调用 / Agent
**一句话总结**：LLM 不擅计算、缺实时信息，解法是「让 AI 调用确定性代码/外部 API」，Agent 是让 AI 自主选择工具的抽象。

**关键框架**：Agent 的 ReAct 循环 = Thought → Action → Action Input → Observation，直到 Final Answer。工具（Tool）的 description 就是「契约」——AI 只看描述（不读实现）决定调用，描述写错会直接导致调用错误。

**可操作方法**：
1. 用代码补数理短板：让 AI 写 Python 代码、再交解释器执行（来源：第 15 讲）
2. 用 max_iterations、return_direct 控制 Agent 的重试与直返（来源：第 17 讲）
3. Function Call 原生工具调用：tools 参数声明函数 + JSON Schema 描述参数（来源：加餐二）

**金句**：
> "想要让 function call 获得一个准确而有效的结果，对 function 的准确描述和命名就非常重要了。" — 加餐二

### 主题五：多模态——文本图像同向量空间
**一句话总结**：CLIP 把文本和图片映射到同一向量空间，是零样本分类、以图搜图、文生图的共同基石。

**关键框架**：Stable Diffusion 三模块 = CLIP 文本编码 + UNet/Scheduler 去噪 + VAE 解码。文生图是「生成」而非「检索」——用「宇航员从未在太空骑过马」即可证明。Visual ChatGPT（Task Matrix）复用 Agent 机制，让 LLM 调度视觉模型实现聊天式改图。

**可操作方法**：
1. 零样本图像分类：列出类别文本名 + softmax 算概率（来源：第 23 讲）
2. 以图搜图：图片转向量 + FAISS 索引（来源：第 23 讲）

**金句**：
> "我们画的是在 Stable Diffusion 里非常经典的一张「宇航员在太空骑马」的图片……是为了证明我们并不是通过「搜索」的方式找到一张已经存在的图片。" — 第 24 讲

### 主题六：产品设计与工程化
**一句话总结**：AIGC 产品的护城河在「数据飞轮」而非模型本身；工程上要靠 JSON 模式 + seed 保证稳定输出。

**关键框架**：AIGC 产品三原则 = 用户社区（降门槛）+ 及时反馈（留用户）+ 数据飞轮（用户操作即标注）。工程上「temperature=0 不等于输出一致」，还需固定 seed + 比对 fingerprint。

**可操作方法**：
1. 用 response_format=json_object 强制 JSON 输出（来源：加餐一）
2. temperature=0 + 固定 seed + system_fingerprint 实现可复现（来源：加餐一）

**金句**：
> "用户社区、及时反馈以及建立数据飞轮是 AIGC 类应用必不可少的组成部分。" — 第 27 讲
