# 11 渐进式披露：把知识做成目录、章节、附录

**结论**：复杂 Skill 不该把全部内容塞进一个 SKILL.md。第一层只暴露 description 当目录，第二层激活后加载主文件当章节，第三层按需读取引用文件当附录。

**证据**：所有 Skill 的 description 共享约 15,000 字符预算；三层结构让"收入增长率怎么算"不必加载成本、现金流、报表模板；Quick Reference 路由表用关键词决定加载哪份 reference。

**关系**：上承 09 的"description 是触发器"，下接 12 的 Skills + SubAgent 组合；本质是知识管理的按需分发。

**批判**：释题"token 利用率提升 98%"无出处、正文自认"大概估算"，禁止引用；框架本身是成熟 UX 模式的迁移，原创性有限但迁移恰当。
