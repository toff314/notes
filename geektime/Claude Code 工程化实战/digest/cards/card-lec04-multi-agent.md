# 04 多 Agent：先问该不该，再问哪一种

**结论**：多 Agent 不是升级打怪，而是架构选型。两个升级信号——单一 prompt 装不下多领域知识、多个团队要独立维护 Agent；在此之前，"先单 Agent，再加工具"。

**证据**：四种模式（Sub-Agents / Skills / Handoffs / Router）；Anthropic 官方数据 90.2% 性能提升、约 15 倍 token 成本，95% 性能波动中 token 占 80%；决策树按领域数、工具数、状态流转、并行查询分流。

**关系**：上承 03 的上下文污染，下接 07 的并行/流水线与 08 的 Teams；hot-05 再把控制流从上下文搬到脚本。

**批判**：50K tokens、工具数阈值是讲师经验值，不应当硬标准；40% token 节省来自 LangChain 图表转述；课程没给"多高价值才值得 15 倍成本"的量化标尺。
