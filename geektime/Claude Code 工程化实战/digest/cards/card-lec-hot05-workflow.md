# hot-05 Workflow：看控制流在哪里

**结论**：Workflow 不是"更强的 Sub-Agent"，而是把编排逻辑从对话搬进脚本。Sub-Agent 的控制流在 Claude 上下文里，Workflow 的控制流在 JavaScript 变量里。

**证据**：中间结果留在脚本变量、不进主对话；换来确定性、可并行规模、会话内可恢复与质量模式固化；代价是不接受中途输入、脚本无文件/Shell 权限、生成本身耗 token；四维判据第一条是"流程是否已经稳定"。

**关系**：补全 04 的四种模式，接在 07 的流水线编排之后；与 Headless 的区别是"编排"而非"无人值守执行"。

**批判**：仍是 research preview，API 与并发上限会变；课程未给并行规模与成本的上限数据，只给了定性判断。
