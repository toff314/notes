衍生选题 · 第 6 讲

筛选判据（四条全过才留）：① 讲而未透；② 可验证（能跑代码或算数）；③ 与我的技术栈有关（Python / 服务端 / 知乎专栏读者能用）；④ 反直觉或可证伪。不产生纯观点稿。

t1 负采样为什么是 3/4 次幂：一条曲线改变训练

  • 主题串：负采样 / 3/4 次幂 / 词频采样 / 高频压制
  • 发布：未发布（状态见文末索引表）
  • 类型：教程（可复现）
  • 角度：从频次分布出发，把 f(w)^0.75 与 f(w)^1 的采样分布画在同一张图上，看高频词被踩中的概率被压掉多少
  • 锚点：§二 L296–L331（03-2 P55）
  • 为什么值得写：几乎所有 word2vec 教程都写"用 3/4 次幂，因为效果好"，没人画过这条曲线长什么样；老师课上只用"开根号"类比过
  • 增益：附 40 行脚本，输入真实词频表（可用本讲转写稿统计），输出两条分布曲线 + 高频词/低频词覆盖率的对照表
  • 目标技能：write-tech-tutorial

t2 窗口大小 = 句法还是主题：复现 Levy 2014 的 Hogwarts 实验

  • 主题串：窗口大小 / 句法 vs 主题 / Levy 2014 / 近邻对比
  • 发布：未发布（状态见文末索引表）
  • 类型：教程（可复现）
  • 角度：同一份语料训两个 skip-gram，只改窗口（2 vs 5），取小说人物/地名的最近邻，看邻居从"学校名"变成"Harry Potter"
  • 锚点：§三 L386–L391（03-2 P60）
  • 为什么值得写：课上只念了结论，Levy & Goldberg 2014 (ACL) 的实验设计与数据都没展开；而"窗口调大调小"是所有人调 word2vec 时唯一会碰的超参
  • 增益：给出可复现的最小语料 + 训练命令 + 近邻表，读者能亲手看到"同一个词，两个窗口，两种语义"
  • 目标技能：write-tech-tutorial

t3 GloVe 的概率比：为什么"比值"是放大镜

  • 主题串：GloVe / 同现概率比 / 放大镜 / 干扰词过滤
  • 发布：未发布（状态见文末索引表）
  • 类型：教程
  • 角度：用课上 ice/steam × solid/gas/water/fashion 的表，手算 8.9 / 8.5×10⁻² / 1.36 / 0.96 四个比值，解释"两者都相关的词比值≈1"如何自动过滤干扰
  • 锚点：§四 L475–L510（03-3 P5）
  • 为什么值得写：GloVe 的科普都从损失函数讲起，绕过了它真正聪明的设计——不是模型新，是统计量换了
  • 增益：附"自己搭 5 分钟小语料复现比值表"的脚本；给出为什么不能直接拿单一概率做特征的三条理由
  • 目标技能：write-tech-tutorial

t4 一个词两个向量：word2vec 的输入侧与输出侧该取哪个

  • 主题串：输入侧向量 / 输出侧向量 / 相加 or 拼接 / 下游任务对比
  • 发布：未发布（状态见文末索引表）
  • 类型：教程（工程向）
  • 角度：把三种取法（只取输入侧／相加／拼接）放进同一个下游任务（文本分类）比一次，看差多少
  • 锚点：§三 L377–L382（03-2 P59）
  • 为什么值得写：课上老师自己说"别人这点我固定好了"，说明这是个没有共识的工程选择，正好可以用实验回答
  • 增益：给出可复现的对比表与结论区间，说明拼接近乎总能小幅优于单侧，但代价是维度翻倍
  • 目标技能：write-tech-tutorial

t5 参数按 N 指数爆炸：用 28 个词和 10⁸ 语料各算一遍

  • 主题串：N-gram / 参数爆炸 / 数据稀疏 / 语料参数比
  • 发布：未发布（状态见文末索引表）
  • 类型：教程
  • 角度：先手算 04-1 P6 那 28 个 token 的 unigram 概率，再把词表放大到 10⁴、语料 10⁸，算"每个参数平均能分到几条 n-gram"，最后落到 P17 那句概率为 0 的句子
  • 锚点：§八 L763–L796、§九 L797–L816（04-1 P6–P17）
  • 为什么值得写：数据稀疏所有人都在说，很少有人真把"语料/参数"这个除商算出来给读者看
  • 增益：一张随 N 变化的"每个参数可用样本数"表，读者一眼看到 N=4 时已经不足 1
  • 目标技能：write-tech-tutorial

t6 26% 与 9%：为什么"人写还是机写"这么难判

  • 主题串：AI 文本检测 / 错误率 26% 与 9% / 检测器滞后
  • 发布：未发布（状态见文末索引表）
  • 类型：观点（有数据支撑）
  • 角度：从 OpenAI 分类器的两个错误率出发，讨论"检测器与被检测模型同步进化"这个结构性劣势
  • 锚点：§七 L681–L693（03-3 P35）
  • 为什么值得写：AI 检测是当下高频需求，但多数讨论停在"准不准"，没讲清为什么这个任务在原理上就吃亏
  • 增益：给出"检测器为什么必然滞后"的三条机制，以及可操作的替代方案（水印、来源签名、过程审计）
  • 目标技能：write-zhihu-tech
