## 开场：一次查不到出处的检索

第 3 讲听完，我脑子里翻来覆去是一句记不准出处的话：**通用模型如果各方面都强，就说明各方面都不强——没有真正的 AGI，时间和成本有限，不可能面面俱到。** 我记得好像在哪本书里读过，疑似周志明的《智慧的疆界》，就躺在我的微信读书本地书库里。我当即去查——结果扑了个空：本地电子版缺了好几章，已下载的部分逐章检索"通用人工智能""AGI""全能"，一条都没有。倒是顺着这个念头在网上搜，搜到了一篇实打实的论文：Kocoń 等人 2023 年的《ChatGPT: Jack of all trades, master of none》（arXiv:2302.10724），把 ChatGPT 拉上 25 个 NLP benchmark，和各路专用微调模型同台，结论就写在标题里。

后来想想，这个"查不到→换一条路找到"的过程，本身就是这节课最好的注脚——课上学生分享的那段"从 BASEBALL 到 RAG"的问答六十年，讲的正是同一件事：人向机器要一个答案，机器从规则库查到向量检索，查的越来越准，但"答案在哪、信多少"这个问题，从来都在人这一侧。我这次也不例外：书的记忆是模糊的，论文的证据是扎实的，我能交代的只有后者。

这句查无实据的话，就用它当这篇随想的骨架。下面分三块：第 3 讲的分词方法史告诉我"通用性从哪来"；我的两组实验回答"专用值多少钱"；最后说为什么我笃定这是"第五次革命"——虽然这个数是我私下的叫法，不是哪本教科书的说法。

## 一、分词三路线：每一步都在买回来一点上下文

先把课上的知识主线讲清楚（讲义 §4–§9）。汉语切分为什么难，第 2 讲已经立过案：词无定界。第 3 讲回答"那怎么办"，方法是按历史排成三代的：

**第一代，基于规则**：前向最大匹配 FMM（和后向镜像 BMM），靠的是两个东西——一部词典，一个参数 MaxLen（词典最长词长，课堂上的经验值是词表平均词长再加一两）。老师现场演示了"语言学很重要"怎么被切成"语言学/很/重要"。规则法的先天缺陷也当场暴露：交集歧义 OA（"的确"：FMM 切"的确/定"，BMM 切"的/确定"）、组合歧义 CA（"一起"既可一词也可两词）、未登录词 OOV（一律切成单字）。加规则救局部，规则总有例外；根子上的诊断是：固定词表不含上下文，而"一起"还是"一/起"，恰恰取决于上下文（讲义 §7）。

**第二代，基于分类**：换视角，不看词，看每个字和字之间的位置——"分还是不分"，变成位置二分类。成熟分类器全部能用：朴素贝叶斯（用先验估后验，"朴素"在特征条件独立）、KNN、最大熵、深度网络（讲义 §8）。代价是 pipeline 的原罪：每个位置单独决策，前面切错了往后传，每步只是局部最优。

**第三代，基于序标**：把切分建模成"给每个字打标签"，标签集 {B, I, O}，BIO 序列标注从此成了主流。HMM 用状态转移概率加发射概率建模，Viterbi 动态规划在 3ⁿ 种候选里保留中间结果、求出全局最优路径；后面还有 MEMM、CRF、深度网络加 CRF 一路接棒（讲义 §9）。

贯穿三代的还有一把尺子：评测。标准答案要经过统一标注口径、专家标注、交叉检验、委员会仲裁；P 以自己输出的词数为分母，R 以标准答案为分母，F1 调和；基线回答"脚下最低"，天花板回答"往上最高"（讲义 §6）。

**我的重述就一句话：这三代方法，每一步进化买回来的是"更多上下文"。** 规则没有上下文，所以撞死在歧义和 OOV 上；分类把左右邻字当特征引进来，买回来局部上下文；序标把整个句子当一个序列整体求解，买回来全局上下文。上下文就是专用性——模型"懂"的场景边界，就是它见过的上下文边界。由此看市面上一切"通用"的标榜，都可以翻译成：它只带通用上下文。所谓通用模型，是只见过通用世界的专用模型。这句话没有出处，是我的重述，但我下面用实验给它称了称斤两。

## 二、通用值多少钱：我的两组实验

### 实验一：给分词器灌领域知识，F1 从 0.449 到 0.923

我拿自己行业的文本测的——云安全是个行话密布的领域，"等保测评""零信任""容器逃逸""态势感知"全是通用词典里不收的词。造了三句话当考题，金标准按领域口径标注，三个选手同台。下面是完整可运行的代码（与 labs/lab-01-domain-segmentation/run.py 同源，2026-10-27 本机实跑）：

```python
import jieba

DOMAIN_TERMS = ["等保测评","零信任","容器逃逸","态势感知","数据脱敏","护网行动","基线核查"]

CASES = [
    ("等保测评要求做基线核查和漏洞扫描",
     ["等保测评","要求","做","基线核查","和","漏洞扫描"]),
    ("零信任架构下容器逃逸风险需要态势感知",
     ["零信任","架构","下","容器逃逸","风险","需要","态势感知"]),
    ("护网行动期间数据脱敏必须到位",
     ["护网行动","期间","数据脱敏","必须","到位"]),
]

def prf(pred, gold):                      # P/R/F1，讲义 §6 口径
    def spans(seg):
        out, i = set(), 0
        for w in seg:
            out.add((i, w)); i += len(w)
        return out
    p, g = spans(pred), spans(gold)
    tp = len(p & g)
    P = tp/len(p); R = tp/len(g)
    return round(P,3), round(R,3), round(2*P*R/(P+R),3)

def fmm(text, lexicon, maxlen=6):         # 课堂 FMM
    res, i = [], 0
    while i < len(text):
        hit = next((text[i:i+L] for L in range(min(maxlen,len(text)-i),0,-1)
                    if text[i:i+L] in lexicon), None)
        if hit: res.append(hit); i += len(hit)
        else:   res.append(text[i]); i += 1
    return res

jieba.initialize()
resA = [list(jieba.cut(s)) for s,_ in CASES]        # A：通用
for t in DOMAIN_TERMS: jieba.add_word(t)
resB = [list(jieba.cut(s)) for s,_ in CASES]        # B：+领域词典
lex  = set(jieba.dt.FREQ.keys()) | set(DOMAIN_TERMS)
resC = [fmm(s, lex) for s,_ in CASES]              # C：FMM+大词表

for name, res in [("A_jieba通用",resA),("B_加领域词典",resB),("C_FMM加领域词典",resC)]:
    F1s = [prf(p, g)[2] for p,(_,g) in zip(res, CASES)]
    print(name, "avgF1 =", round(sum(F1s)/len(F1s),3))
```

真实输出：

```text
A_jieba通用        avgF1 = 0.449
B_加领域词典        avgF1 = 0.923
C_FMM加领域词典     avgF1 = 0.923
```

拆开看细节更有意思（完整明细在 labs/lab-01-domain-segmentation/out/raw.log）：

```text
等保测评要求做基线核查和漏洞扫描
  A: 等/保/测评/要求/做/基线/核查/和/漏洞/扫描      F1=0.375
  B: 等保测评/要求/做/基线核查/和/漏洞/扫描          F1=0.769
零信任架构下容器逃逸风险需要态势感知
  A: 零/信任/架构/下/容器/逃逸/风险/需要/态势/感知   F1=0.471
  B: 零信任/架构/下/容器逃逸/风险/需要/态势感知      F1=1.0
护网行动期间数据脱敏必须到位
  A: 护网/行动/期间/数据/脱敏/必须/到位            F1=0.5
  B: 护网行动/期间/数据脱敏/必须/到位               F1=1.0
```

明细里还藏着一个诚实的细节：B 组第一句得了 0.769 而不是满分——因为我只往词典里灌了七个领域词，"漏洞扫描"这种领域内的普通复合词不在清单里，就被切成了"漏洞/扫描"。专用化是清单驱动的，清单漏一条，现场就错一处。这个教训和 MaxLen 的经验值一样，都是同一个道理：专用性是人逐条喂出来的，喂不到的地方，通用性顶不上去。

三个数字三件事。**其一，通用确实会输**：0.449 的 F1，术语全军覆没，等保测评被切成"等/保"——跟通用模型在专业 benchmark 上输给专用模型，是同一件事的两幅画面，Kocoń 那篇论文给过大模型的版本，我的笔记本给了分词的版本。**其二，专用化的成本低得离谱**：jieba.add_word 七行代码，F1 翻倍。**其三，最扎眼——赢的不是新算法**：四十多年前的 FMM 配上今天的通用大词表，和统计学习出身的 jieba 打成了平手。增益的来源是领域知识本身，不是方法的新旧。这和[第 5 课那篇 HowNet 随笔](https://www.askfount.com/articles/articles-20261027-1793074467919)的结论遥相呼应：义原追不上的新词，靠向量补；通用追不上的领域，靠词典补。**"专用"从来都不是算法的对立面，它是上下文的对齐度。**

### 实验二：FMM/BMM 复现，看歧义怎么躲猫猫

第二组实验把课堂算法原样复现了一遍。完整代码如下（与 labs/lab-02-fmm-bmm/run.py 同源，21 个词的词典，MaxLen=3）：

```python
LEX = {"结婚","的","和","尚未","和尚","未","研究","生命","起源","研究生",
       "学生","会","学生会","说","英语","北京","人和","足球","俱乐部","疫情","如此"}

def fmm(text, lexicon, maxlen=3):
    res, i = [], 0
    while i < len(text):
        hit = next((text[i:i+L] for L in range(min(maxlen,len(text)-i),0,-1)
                    if text[i:i+L] in lexicon), None)
        if hit: res.append(hit); i += len(hit)
        else:   res.append(text[i]); i += 1
    return res

def bmm(text, lexicon, maxlen=3):          # 从右往左的镜像
    res, i = [], len(text)
    while i > 0:
        hit = next((text[i-L:i] for L in range(min(maxlen,i),0,-1)
                    if text[i-L:i] in lexicon), None)
        if hit: res.append(hit); i -= len(hit)
        else:   res.append(text[i-1]); i -= 1
    return res[::-1]

for s, kind in [("结婚的和尚未结婚的","OA"),("研究生命起源","CA+贪婪陷阱"),
                ("学生会说英语","CA"),("北京人和足球俱乐部","实体"),("新冠疫情反复","OOV")]:
    f, b = fmm(s, LEX), bmm(s, LEX)
    mark = "  <== 分歧" if f != b else ""
    print(f"[{kind}] {s}\n  FMM: {'/'.join(f)}\n  BMM: {'/'.join(b)}{mark}\n")
```

真实输出（2026-10-27 本机实跑）：

```text
[OA 交集歧义（FMM/BMM 分歧可发现）] 结婚的和尚未结婚的
  FMM: 结婚/的/和尚/未/结婚/的
  BMM: 结婚/的/和/尚未/结婚/的  <== 分歧

[CA 组合歧义 + FMM 贪婪陷阱] 研究生命起源
  FMM: 研究生/命/起源
  BMM: 研究/生命/起源  <== 分歧

[CA 组合歧义（双向均不可见）] 学生会说英语
  FMM: 学生会/说/英语
  BMM: 学生会/说/英语

[实体歧义（词典未收实体则不可见）] 北京人和足球俱乐部
  FMM: 北京/人和/足球/俱乐部
  BMM: 北京/人和/足球/俱乐部

[OOV（新/冠 退化为单字）] 新冠疫情反复
  FMM: 新/冠/疫情/反/复
  BMM: 新/冠/疫情/反/复
```

这五道把讲义上的分类学（P64–P67）搬到了屏幕上。"结婚的和尚未结婚的"是汉语分词的老笑话：顺着切，出来一个"和尚"；倒着切，"和尚未婚"变成了"和/尚未"——FMM 和 BMM 各信一种读法，分歧一暴露，OA 就现形了。这比课堂上任何定义都直观地说明了一件事：**检验两个独立方法的一致性，是最便宜的验证手段**——规则时代就有的一致性检测，六十年后的今天依然是校验 AI 输出的第一性工具。"研究生命起源"暴露了最大匹配的贪婪：FMM 贪到"研究生"，把"命"掉在半空，BMM 则给出通顺的"研究/生命/起源"——贪婪地看一切局部最优，和通用模型"什么都要答"的贪婪，气质上是同一种东西。"学生会"双向一致地赌错，演示 CA 的不可见；"北京人和"提醒人实体歧义是 OOV 的堂兄弟——词典不收"北京人和足球俱乐部"这个队名，歧义连登场的机会都没有；"新冠疫情"里"疫情"幸存、"新冠"碎成单字，把语言生命力问题直接拍在脸上。

## 三、"第五次革命"：当话题消失，革命才算完成

现在可以把那句话说圆了。**我的悖论版本是：模型的能力是一个定长的预算，面铺得越广，单点能买到的深度就越薄——除非预算无限，而预算是数据、算力、注意力和时间，哪一样都不是无限的。** Kocoń 那篇论文给了这个直觉一个 25 项 benchmark 的实证形态；我的 FMM 实验给了它一个 21 词词典的形态：通用词表里每多一个词，都是一次预算的分配。课上也有一模一样的智慧：MaxLen 设多大是个权衡，词表收哪些词也是个权衡——工程的一切通用性，都是权衡出来的。

但"通用不够专用来凑"只是硬币的一面。另一面是：绝大多数场景根本用不着一百分。写周报、改文案、查资料，八十分的通用模型[按量计费](https://www.askfount.com/questions/questions-535)，比养一个九十五分的专用系统便宜三个数量级。专用只该出现在关键路径上——做工程的人管这个纪律叫默认拒绝、按需放行：通用是底色，专用是闸门。课上那句"低于基线就不必凑热闹，先跑通基线再改"，说的是同一个纪律。

更值得一提的是观察侧的体感。我私下把这轮变化叫"第五次革命"，前四次我经历过的是 PC、互联网、移动、云——每次的标志都一样：**话题消失**。2015 年人人言必称云，今天没人谈了，不是云失败了，是云成了水和电，谈它就像谈插座。AI 正在同一条路上：电梯里的广告是 AI 生成的；给高校合作项目帮忙时，学生的任务清单里 AI 工具是默认项；翻论文目录，几乎每篇都和 AI 沾边。当一件事连反对它的人都懒得再提的时候，它就是基础设施了。

这也回答了我为什么来学这门课。业余给自己挖了一整套知识管理的渠，但真正让我坐进教室的，是一个更老的问题：**语言是什么？** 我的答案是：语言是信息的传递，是上一代把知识交给下一代的通道——通道的效率就是文明的速率。这门课研究的东西剥到底，是"信息如何被更高效地传递"：分词研究怎么把连续的语流切成可计数的单位（第 2、3 讲），语言模型研究怎么预测下一个词最省惊喜（困惑度那一章），词向量研究怎么把意义压进更低维的信道（第 5 讲）。[省 token 就是省带宽](https://www.askfount.com/questions/questions-537)，层次 softmax 用哈夫曼树给高频词修快速路，和通信里给高概率符号配短码是同一个思想。我硕士在通信所待过，这门课听得我满脑子都是信道。

课上的学生分享把这条线的终点讲得很完整。问答系统六十年：1961 年 BASEBALL 查结构化棒球数据，1971 年向量空间模型，1995 年 BM25，2011 年 Watson 在"危险边缘"夺冠，再到今天的 RAG——检索 top-k 片段拼进提示词，"理解交给大模型、事实交给检索、关键场景用确定程序兜底"（讲义 §10）。六十年五代方案，每一代都在重新回答同一个问题：**知识怎么被更高效地复用？** 我在自己的工作里看到的接力是 RAG → MCP → skills → agent：检索增强之后是工具协议，工具协议之后是可装载的技能单元，技能单元之后是自主编排的代理——每一个新名词，都是"把已有的知识更快搬进新任务"的又一次工程化。老师站在讲台上讲 FMM 的那个上午，也是同一条链路上的一环：他在把他脑子里的知识，压缩成两个小时的高效传递。

**所以我的判断是：AI 和语言的合体，本质是一场沟通效率的革命，而沟通效率是社会进步的元变量。** 知识生产得越快、传得越准、复用得越省，文明就转得越快。这一轮革命的特别之处在于：它优化的正是"知识传递"这件事本身——用机器把信道拓宽，把人从搬运工变成校验员。

## 收尾：一个我不安的追问

课上老师提醒过一句话：AI 重度参与的学习成果，正式场合要自己先过一遍、把好关（讲义 §10）。我当时记下来了，这篇随想交稿前也照做了。但把这句话放大到整个社会的尺度，它让我不安：

信息传递的瓶颈，正在从生产端移到验证端。以前写一篇文章要一天，核对它要一刻钟；现在生成只要十秒，核对的时间反而比写的还长。这不是我一个人的体感——2026 年 10 月，Reddit 最大的开源社区 r/opensource 公告禁止一切 AI 相关项目帖子，理由之一是版主们已经分辨不出一段文字是 AI 写的还是人写后翻译的，连"非英语母语者的帖子"一并拒之门外（The Verge 有报道，抗议者另立了 r/TrueOpenSource）。一个运营十几年的技术社区，宁可错杀也无法校验——这就是验证端瓶颈掐住组织咽喉的实况。

当 AI 让"生产知识"趋近于免费，**校验知识就成了最贵的环节**——而校验本身也是一种信息传递，它也会、也正在被 AI 接管。用 AI 校验 AI，谁来校验校验者？这个问题课上没有答案。我目前只摸到两块砖：一是校验要独立——FMM 加 BMM 双向跑一遍，分歧即报警，和这篇随想过 A4 评审时独立审核员揪出我五处问题，是同一条纪律；二是重要的东西得有不能伪造的锚——P/R/F1 要有一把造得出处的金标准尺子。但这两块砖能撑多大，我说不好，留给后面的课。
