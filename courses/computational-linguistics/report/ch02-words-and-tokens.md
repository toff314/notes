# SLP3 阅读报告 · 第 2 章《词与词元》（Words and Tokens）

## 一、本章内容综述

我在前面课的一次口头报告中分享过本章，并结合自己的工提出了一些问题：任何系统都存在不直接可见、但对运行结果起决定作用的部件，就是暗结构——我将章节综述、课堂笔记和重点内容重读后的新问题整理到了一起。之前并未深入考察NLP背后"词"是如何被切分的。读完本章后我认识到，这个看似简单的问题才是全书的基础问题。本章的主线就是先把"词"这一概念本身的定义的困难讨论清楚，再逐步地给出工程上的解决方案。

第一块内容是"词"的定义困境。 教材开篇的例句说明，连"数词"都需要先约定好口径：是否要计入标点、是否要计入填充词、大小写是否要合并，每一步都会改变答案，因此，书中的"答案是这取决于具体任务"的表述是事实陈述而并非回避。此外有两个更困难的问题。第一，汉语、日语、泰语的书写系统没有正字法意义上的词，书中指出"姚明进入总决赛"一句存在 Treebank（3 词）、北大（5 词）、字序列（7 字）三种合理切分。其二，词表是无界的，Heaps 定律 |V| = kN^β（β 常见于 0.44~0.56）表明词类型随语料的规模按照幂律无限增长，任何固定的词表都无法覆盖语言的全部词，测试集中的未登录词（OOV）也会导致模型无法处理这些词。顺着这个，§2.2 引入了语素（最小意义单位），区分了屈折与派生，但书中也明确指出，跨语言形态的差异过大，"把语素用作跨语言词元化的标准是非常困难"。

第二块内容是字符层与数据驱动的切分（§2.3–2.5）。 第三节将 Unicode 码点、字形和UTF-8 字节三层拆开：码点是编号、字形是显示、编码是字节的规则，自同步设计使损坏文件最多错 3 个字节后即可重新对齐，且 ASCII 文件即天然合法。接下来是全章的核心：BPE 训练时迭代合并当前最频繁的相邻对，编码时只重放训练时学到的合并顺序，测试数据的频率不起作用；字节级 BPE（GPT-2 起）把初始词表降为 256 个字节，从机制上解决了 OOV 问题，但是代价是低资源语言被切分得更碎，书中西班牙语例子中 16 词被切成 33 个词元。书中讨论语料库时，说语料是特定人群在特定场景留下的痕迹，不是语言的均匀抽样，因此数据说明书是需要的。

第三块的内容是工程工具与最小编辑距离（§2.6–2.9）。 工程工具部分包括正则表达式（Kleene 星号、锚点、贪婪匹配、捕获组与预词元化）、Unix 三件套（tr/sort/uniq）以及基于规则的词元化与句子切分。Penn Treebank 标准是这一部分内容的综合体现：附着词切出：doesn't → does + n't、连字符词则保持整体、标点独立成词；句子切分的难点在于缩写词末尾的点"既在词内、又是句界"。最小编辑距离是全章算法含量最高的部分，它把"两个字符串有多像"转化为每步三选一（插/删/替）的累加，用动态规划填表、回溯指针还原对齐。书中 intention → execution 的例子，替换代价为 2 时距离是 8，经典 Levenshtein 版本距离是 5。这个例子说明了：代价表如何设定比算法本身更影响结论，这是本节最重要的观点。

## 二、与课堂内容的对照

本章的内容与课程第 2、3 讲几乎是逐节对应的，但是两者的视角互补。第 2 讲把"断词"定义为"在符号序列中确定词的外部边界"，并且用"差点没上上上上海的车"这一句展示了中文断词的困难；英语断词看起来平凡（靠空格和标点），例外却很多（I'm、i.e.、Ph.D.、AT&T），这正好对应书中关于词内标点要保留的内容。此外，老师课上还特别提醒过：这里的 token（词）和今天大模型语境下的 token（子词）含义已经不同，这个提醒正好点出了书中从 §2.1 到 §2.4 之间的一条重要线索。到了第 3 讲，汉语切分被当成了一个可评测的工程任务：从基于规则的 FMM/BMM（最大匹配，性能被 MaxLen 和词典两个经验参数决定），到位置二分类，再到 BIO 序列标注，同时还配了一整套评测方法（标准答案怎么造、P/R/F1、baseline 与 ceiling）。教材中说"切分取决于任务"，课堂则回答了"那怎么让结果可信"的问题。我在工作中做中文分词评测的时候，曾经遇到同一句被标成 3 词和 5 词的两套答案，当时以为有人标错了，现在才明白那是 Treebank 口径和北大口径的差别，而不是对错的问题。这也正是课堂上强调的"统一标注标准要先于一切算法"。

## 三、重读与验证：两个印象最深的实验

口头报告中我沿上述视角做了几组动手验证，这里只记录两个重读后仍认为分量最重的实验。第一个实验是关于 Heaps 定律的跨语言实测。我没有直接接受书上给出的 β 区间，先拿合成英文语料拟合得 β=0.5048，落在书中 0.44~0.56 区间内，英文这条线教材和实验对上了。但是把同样的方法搬到中文，结果就出现了明显的差异：按"字"统计 β 只有 0.34，按二字组近似"词"β 达到 0.81，同一个语料只是换了计量单位，指数就差出两倍多。换真实的语料再独立验证一遍：三国演义（jieba 词级，4.2 万词）β=0.77，《Pride and Prejudice》英文 β=0.53。后来查文献发现，这个现象有一个正式的名字：Lü、Zhang、Zhou 在《Scaling Laws in Human Language》中指出，Heaps 定律的统计"压倒性地集中在印欧语系"，中日韩表意文字的类型数增长是三阶段的（表观 β 约为 1 → 0.7 → 0.3），而我的实测结果正好各自落在对应的位置：中文词级 0.77~0.81 落在中间段，中文字级 0.34 落在饱和段。倒不是谁测错了，只是各自测对了三阶段其中的一段。

第二个是关于 token 的计量问题。按 OpenAI 官方经验值来说，cl100k 分词器是对中日韩文本大约 1.5~2 个汉字才合 1 个 token，中文比英文费 token 是由分词器的结构决定的。这个问题不只是一个技术细节：同一句话，不同语言按照不同的"单价"计费，语言之间的差异在于词元化那一刻就已经进入了系统。更隐蔽的是推理侧的开销：技能文件、系统提示每一轮对话都要原样随行，让我印象深刻的是，我用 Kimi 写一份报告时它开了 10 个 agent，每个 agent 都重复承担一遍初始化开销，一份报告消耗掉我一个月额度的三分之一。从那以后我养成了一个习惯：做数据相关工作先问计量口径，报数字之前先把分母说清楚。

## 四、我的问题

以英文语料为基础写成的"普适规律"，在中文里还有多少是成立的？而我的实测显示，Heaps 定律的 β 在中文里随切分单位从 0.34（字级）跳到 0.81（词级），而教材给出的 0.44~0.56 只是印欧语系词级语料的拟合值。课堂上一再强调"先统一标注标准，再谈评测指标"，而 Heaps 这件事就说明，只要换一个计量的维度，指标的含义就整个变了。这和换一个采集口径之后、报表里每个数字的含义全变，是同一类问题。那么，NLP 文献里究竟还有多少结论，其实是被"计量口径"悄悄决定了的？面对一本以英文为主写成的教材，我们这些以中文为母语的学生，该建立怎样的"先问口径、再引用数字"的纪律？

次问题，供讨论：课堂上提到 token 一词的含义已从"词"变为"子词"。如果连自己一个月消耗了多少 token 都说不清，那么谈论优化就缺乏计量的基础。
