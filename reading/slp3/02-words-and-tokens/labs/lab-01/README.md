# Lab 01 · 从零实现 BPE

## 目的
对应 `actions.md` 行动 1，验证 §2.4 的三件事：训练从单字符出发、每轮合并最高频相邻对、编码只重放训练学到的合并顺序。

## 运行
```bash
cd labs/lab-01
python3 bpe_lab.py
```

## 语料
12 行中英混合短文本（英文词形变化 + 中文句子），预词元化规则：连续英文字母成块、汉字逐字、标点单独成块。初始字符表 126 个符号。

## 产物（`out/`）
| 文件 | 内容 |
|---|---|
| `merge_history.csv` | 40 次合并的 pair、频次、词表大小、总词元数、字符/词元 |
| `vocab.csv` | 排序后的字符与合并词元 |
| `segments.csv` | 训练词表里每个词的分词结果与频次 |
| `test_segments.csv` | 3 条测试句的切分 |
| `compression_curve.png` | 总词元数、字符/词元随合并次数的变化 |
| `metrics.json` | 汇总指标 |

## 关键输出（真实运行）
- 40 次合并后，训练语料从 291 个字符降到 210 个词元，减少 **27.84%**，平均 **1.386 字符/词元**。
- 最早的合并依次为 `t+o`、`to+k`、`tok+e`、`toke+n`、`w+e`、`token+i`……说明高频英文词根 `token` 很快被整体合并。
- 测试句 `lowest newer tokenization` → 3 个词元；`unseen word: tokenizer` → 12 个词元（`tokenizer` 因训练中出现过相同合并序列而被整体保留）。
- 中文测试句 `词元化是自然语言处理的第一步` → **14 个词元，逐字未合并**。

## 结论
图中压缩曲线在前 10 次合并下降最快，之后趋缓，符合「先吃掉最高频相邻对」的贪心性质。中文没有下降，因为本语料里中文相邻字对的重复次数低于英文词对；这与 §2.4.3 描述的多语言词表偏斜一致：训练语料以英文为主时，其他语言会退化成短词元。

## 反思
我原以为「中英混合语料」会让中文也得到一些合并；实际跑完才发现，频率是全局竞争的，中文句子的重复量根本排不进前 40。下次要么把合并次数加到几百，要么按语言分层统计，否则中文永远只是陪跑。
