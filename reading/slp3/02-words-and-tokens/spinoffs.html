1. 中文为什么被大模型 tokenizer 切碎

  • 交付给：write-zhihu-tech（Mode A）
  • 主题串（可直接复制）：观点：中文为什么被大模型 tokenizer 切碎——词表分配、UTF-8 与多语言成本
  • 书籍锚点：本书 §2.4.3「西班牙语原文的 16 个词被编码成了 33 个词元」；§2.1「汉语、日语和泰语这类语言的书写系统根本没有正字法意义上的词」。
  • 为什么：命中 S1 + S3 + S4 + S6。S1：书只给了一个西班牙语例子，没有展开中文的量化；S3：可从 UTF-8 字节、BPE 合并顺序、词表配额三层讲清机制；S4：词表偏斜是工程取舍还是数据霸权，有真实争议；S6：Rust et al. (2021)、Ahia et al. (2023) 等可查。
  • 增益：① 相对本书：把「西班牙语 33 词元」的孤例扩成中英日多语对照，并给出可复现的 tiktokenizer 计数方法；② 对读者：能解释为什么同一段中文的 API 账单更高、上下文更短，以及选模型时该看 tokenizer 还是看参数。
  • 素材种子：历史溯源（BPE 从 Gage 1994 到 Sennrich 2016）｜人物（Karpathy 的 minbpe 讲座）｜原理（字节级 BPE 与词表配额）｜争议（低资源语言碎片化）。
  • 缺口（下游必须自己搜）：GPT-4o／Claude／Qwen 的实际中文 token 比；不同 tokenizer 的公开词表大小；中文分词标准（Treebank vs 北京大学）的差异数据。
  • 体量建议：标准长文（约 5000–7000 字）。
  • 待核：❓ 各模型 tokenizer 的具体词表构成未公开，只能以实测计数代替。
  • 发布：⬜ 未发布 ｜ 链接：待填

2. BPE 不是语素发现器

  • 交付给：write-zhihu-tech（Mode A）
  • 主题串（可直接复制）：观点：BPE 不是语素发现器——频率压缩与语言学边界是两套证据
  • 书籍锚点：本书 §2.4.1「BPE 训练算法迭代地合并频繁相邻的词元」；§2.2「这一事实使得把语素用作跨语言词元化的标准变得非常困难」。
  • 为什么：命中 S1 + S4 + S5。S1：书明确说子词「通常与语素或词的大小相当」，但没有系统反驳「BPE 学到语素」的流行说法；S4：与「tokenizer 有语言学意义」的常见叙事相反；S5：直接关系到可解释性与安全审计的落点。
  • 增益：① 相对本书：把「大小相当」与「边界相同」拆开，给出反例（跨字符边界、高频词整体合并）；② 对读者：不再把 tokenizer 的切分当作语言结构证据，评估「模型是否理解词法」时少一个误区。
  • 素材种子：历史溯源（BPE 原为压缩算法）｜人物（Sennrich 把 BPE 引入 NMT）｜原理（贪心合并 vs 形态切分）｜争议（tokenizer-free 模型是否必要）。
  • 缺口（下游必须自己搜）：BPE 切分与人工语素标注的一致率实验；byte-level tokenizer 的非法 UTF-8 比例。
  • 体量建议：标准长文（约 5000 字）。
  • 待核：❓ 「一致率」类实验多为小语料，结论不宜外推。
  • 发布：⬜ 未发布 ｜ 链接：待填

3. 从 ELIZA 到 GPT-4o：词元化五十年

  • 交付给：write-tech-tutorial（Mode A）
  • 主题串（可直接复制）：论文：从 ELIZA 到 GPT-4o——词元化五十年的三次转身
  • 书籍锚点：本书章首 ELIZA 对话与 §2.6.7 的 ELIZA 替换规则；历史注记「BPE 最初是 Gage (1994) 提出的一种文本压缩方法」。
  • 为什么：命中 S2 + S3 + S4。S2：Weizenbaum、Gage、Sennrich、Karpathy 都有可查史料；S3：从模式匹配到正则替换、再到 BPE 与 SuperBPE，技术有纵深；S4：ELIZA 的「假理解」与今天 tokenizer 的「假语素」形成有趣反差。
  • 增益：① 相对本书：把散落在章首、§2.6.7、历史注记里的线索串成一条演化链；② 对读者：理解「切分单位」如何从手写规则变成统计产物，以及每次转变解决了什么、又留下了什么。
  • 素材种子：历史溯源（1966 ELIZA、1994 BPE、2016 subword NMT）｜人物（Weizenbaum 的反思、Karpathy 的公开课）｜原理（模式匹配 → 正则 → 子词）｜争议（ELIZA 效应与拟人化）。
  • 缺口（下游必须自己搜）：ELIZA 原始代码与对话记录；Gage 1994 原文；SuperBPE／BoundlessBPE 论文细节。
  • 体量建议：专栏级（3–4 篇，每篇 4000–6000 字）。
  • 待核：❓ 书中所引年份与会议信息需逐条回原文核对。

4. 编辑距离为什么还是拼写纠错的地基

  • 交付给：write-zhihu-tech（Mode A）
  • 主题串（可直接复制）：观点：编辑距离为什么还是拼写纠错的地基——从 DP 到神经纠错的成本账
  • 书籍锚点：本书 §2.9「intention 与 execution 之间的距离为 5」；§2.9.1「每次插入或删除的代价为 1，且不允许替换」的版本。
  • 为什么：命中 S1 + S3 + S5 + S6。S1：书只讲算法与对齐，没有讲它在现代纠错产品中的位置；S3：可从 DP、加权代价、Damerau 扩展讲到神经纠错；S5：拼写纠错是搜索、输入法、IDE 的真实落点；S6：Gusfield (1997)、NIST sclite 等可查。
  • 增益：① 相对本书：把「距离 5 还是 8」的代价差异接到拼写纠错的候选排序上；② 对读者：知道什么时候该用编辑距离（可解释、低资源、需对齐），什么时候该换模型。
  • 素材种子：历史溯源（Levenshtein 1966、Wagner-Fischer 1974）｜人物（Bellman 命名动态规划的故事）｜原理（DP 与加权代价）｜争议（神经纠错是否还需要编辑距离）。
  • 缺口（下游必须自己搜）：主流输入法的纠错候选策略；Damerau-Levenshtein 的工业实现；键盘邻接代价表。
  • 体量建议：标准长文（约 5000 字）。
  • 待核：❓ 各家产品的纠错细节不公开，只能引用论文与开源实现。

  • 书籍锚点：本书 §2.3.1「码点并不指定字形」；§2.3.2「它是自同步的」与图 2.5 的位映射表。
  • 为什么：命中 S1 + S2 + S6。S1：书把 UTF-8 讲清了规则，但没展开「字形／码点／字素簇」的常见混淆；S2：Ken Thompson 与 Rob Pike 在餐垫上画出 UTF-8 的故事可查；S6：Unicode 核心规范、Python 文档可逐条核对。

  • 素材种子：历史溯源（ASCII → Unicode → UTF-8）｜人物（Thompson／Pike）｜原理（变长编码、自同步、字素簇）｜争议（UTF-8 是否浪费中文空间）。
  • 缺口（下游必须自己搜）：Unicode 16.0 规范条文；各语言 len() 的语义差异；emoji ZWJ 序列的码点构成。

  • 待核：❓ 书中「15 万字符／168 种文字」为特定版本口径，需按最新 Unicode 版本更新。
