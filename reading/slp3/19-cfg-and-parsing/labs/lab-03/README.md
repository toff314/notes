# lab-03　CKY 复杂度实测（n=4→39）

对应行动：`actions.md` 第 3 条。对应书中 §19.6（CKY 的时间与空间复杂度）。

## 怎么跑

```bash
cd labs/lab-03
python3 scaling.py
```

依赖：`../cfgkit.py` + numpy + matplotlib（Agg 后端）。约 2 秒。

## 输入

- 文法：L1X 文法（同 lab-02，多开一条 `NP → NP PP`），让表内容更满，计时差异更明显。
- 句族：固定句式 `i shot an elephant` + 逐步追加 13 个 PP（`in my pajamas`、`near houston`、`on united` 等），n 从 4 到 39。

## 结论

1. **空间 O(n²) 得到验证**：cell 数 = n(n+1)/2，斜率 1.92（接近 2）；n=39 时只有 780 个 cell。
2. **时间主项 O(n³) 得到验证**：分裂次数（Σ (span-1)(n-span+1)）的斜率 3.02，精确复现 n³ 主项。
3. **实测时间斜率只有 2.41**，低于理论值 3.0。原因是本句族的表格密度只有 O(n)：每个跨度只塞得下常数个非终结符（平均 table_entries/cells ≈ 0.73），所以真实耗时 ≈ entries × splits ≈ O(n) × O(n²) = O(n³)，但常数因子比稠密表小得多。
4. **DP 填表 vs 枚举的本质差距**：n=39 时分析数 5.88 亿（枚举不可行），但 CKY 填表只要 0.003 秒。这验证了 §19.6.3 的核心价值——「紧凑地表示句子的所有可能分析」不是夸张，而是 CKY 相对于暴力枚举的本质优势。

## 反思

我原以为时间斜率会直接给出 3.0，实测只有 2.41。原因是本句族的表格密度只有 O(n)（每个跨度只塞得下常数个非终结符），真实耗时约等于 entries × splits，而 entries 在本例中远低于理论最大值 n²。这说明「O(n³) 是上界」不是「每个实例都达到」——上界要求表格稠密，而自然语言的文法往往让表很稀疏。

另一个收获是：n=39 的句子在自然语言里已经算长了，但分析数已经到 5.88 亿——这还只是玩具文法。真实 PTB 文法在真实句子上，歧义数只会更夸张。这就是为什么工业级 parser 必须用 CKY 或近似算法，不能用暴力枚举。
