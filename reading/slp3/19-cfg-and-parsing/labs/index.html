每条行动的结论与反思

行动 1（lab-01）：CNF 转换 + CKY 填表 + 枚举

  • 结论：L1 文法（16 条非词汇规则 + 36 条词汇规则）转成 CNF 后得到 64 条规则；「book the flight through houston」填表后 cell [0,5] 含 {S, VP}，回溯指针枚举出 3 棵完整解析树，与书中图 19.14 描述的三种分析一致；20 个测试句在转换前后成员判定 20/20 一致。
  • 反思：我原以为 CNF 转换只是「换个写法」，跑完才发现单元产生式消除会把词性提升到 VP 甚至 S——同一个词在表里同时是 Verb、VP、S。这不是实现 bug，而是 CNF 转换的固有结果（§19.6.1）。后处理时必须用 unbinarize 把哑节点折叠掉，否则树里会多出 X1/X2 这类没人认识的非终结符。

行动 2（lab-02）：结构歧义枚举与计数

  • 结论：Groucho 例句「i shot an elephant in my pajamas」共有 3 种合法分析，PP 宿主产出式分别为 VP->Verb-NP-PP（我穿睡衣开枪）、Nominal->Nominal-PP（大象穿睡衣）、VP->VP-PP（右附加）。PP 从 0→4 个时，L1 文法的分析数 1→3→8→15→24，L1X 文法（多开一条 NP->NP PP）1→4→17→63→226；L1X 的增长接近 Catalan 数（1,1,2,5,14），而 k! 是更松的上界。
  • 反思：我原以为「分析数随 PP 个数指数增长」是夸张说法，实测才发现 L1X 在 4 个 PP 时已经有 226 种分析——这还只是玩具文法。真实宾州树库的扁平文法（§19.3 说的 4,500 条 VP 规则）在真实句子上会爆炸得更厉害。这也解释了为什么 CKY 的价值不是「找到一棵树」，而是用多项式大小的表压住指数多的树（§19.6.3）。

行动 3（lab-03）：CKY 复杂度实测

  • 结论：n=4→39 的 log-log 拟合：时间斜率 2.41，分裂次数斜率 3.02（验证 O(n³) 主项），单元格数斜率 1.92（验证 O(n²) 空间）。n=39 时分析数 5.88 亿，但 CKY 填表只要 0.003 秒——因为 DP 只填表不枚举。
  • 反思：我原以为时间斜率会直接给出 3.0，实测只有 2.41。原因是本句族的表格密度只有 O(n)（每个跨度只塞得下常数个非终结符），真实耗时约等于 entries × splits，而 entries 在本例中远低于理论最大值 n²。这说明「O(n³) 是上界」不是「每个实例都达到」——上界要求表格稠密，而自然语言的文法往往让表很稀疏。

行动 4（lab-04）：跨度打分 + CKY 解码 vs 贪心解码（已知缺陷）

  • 结论：在一个由 L1X 随机采样、二叉化得到的合成树库上（train 1500 / test 250），用 225 维离散特征 + 结构化感知机训练跨度打分器，得到：
  • 训练集 exact match = 0.7965（decode 与 gold spans 完全一致的比例）
  • 测试集 CKY 解码 exact match = 0.0
  • 测试集贪心解码 exact match = 0.0
  • 贪心解码合法树率 = 0.372（即 62.8% 的句子贪心输出拼不成覆盖全句的树）
  • 已知缺陷：lab-04 存在严重问题，结果不可信：
  1. 测试集 exact match 为 0.0，说明模型在测试集上完全失败；但训练集 exact match 有 0.7965，说明不是代码 bug 而是严重的过拟合或数据分布问题。
  2. 贪心合法树率 0.372 远低于书中引用的 95%（Gaddy et al., 2018），差距过大，怀疑是合成数据分布太窄或特征设计缺陷。
  3. 由于 exact match 为 0.0，无法进一步计算 PARSEVAL 的 P/R/F1 和交叉括号。
  4. 该 lab 由前置 agent 生成，尚未经过人工排查与修复；后续 agent 需要检查：① 数据生成是否有泄漏（train/test 同分布？）；② 感知机更新是否正确；③ 特征是否足以泛化。
  • 反思：lab-04 的失败本身是一个重要教训——书中引用「95% 的预测括号结构能形成有效的树」是基于真实 PTB 数据与深度神经特征；在合成数据 + 手工特征上，这个比例会崩塌。这提醒我不能把论文中的数字当作跨任务常数引用。

已知缺陷

  • lab-04：如上所述，exact match 为 0.0、贪心合法树率仅 0.372，结果不可信。已知问题：疑似过拟合或数据分布问题。该 lab 由前置 agent 生成，尚未修复，后续 agent 需要排查数据生成、感知机更新、特征设计三个环节。
  • lab-05：待建。原计划用 lab-04 的 test_pred.json 计算 PARSEVAL 的 P/R/F1 和交叉括号；由于 lab-04 输出不可信，lab-05 暂无法开始。后续 agent 需要先修复 lab-04，再补 lab-05。

已知局限

  • 语料规模小：lab-01~03 基于 L1/L1X 玩具文法（几十条规则、几十个词），结论只能作方向性参考，与真实宾州树库（数万规则、百万词）差距很大。
  • lab-02 的增长实验只到 4 个 PP；更长句子的分析数会爆炸（lab-03 显示 n=39 时 5.88 亿），但枚举超过 20 万棵已经受限（limit=200000）。
  • lab-04 的合成数据由 L1X 随机采样，分布单一，无法代表真实句法分布；其结果（0.0 / 0.372）不能用于否定书中 95% 的结论，只能说明「在合成数据 + 手工特征上，贪心解码会失败」。
