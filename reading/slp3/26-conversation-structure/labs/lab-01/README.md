# lab-01　话轮切分与断点检测模拟

对应行动：`actions.md` 第 1 条。对应书中 §26.1.1（话轮、断点检测）。

## 怎么跑

```bash
cd labs/lab-01
python3 lab01_turn_endpointing.py
```

依赖：仅 Python 3 标准库。

## 输入

图 26.1 的 20 个话轮（手工录入脚本 `GOLD_TURNS`），含 C19 这种「以填充词开头且包含多句」的易错样本。

## 产物

| 文件 | 内容 |
|---|---|
| `out/turn_metrics.json` | precision / recall / F1 + 错误列表 |

## 关键输出（真实运行）

```
gold_turns=20
predicted=20 false_positive=1
precision=0.9524 recall=1.0000 f1=0.9756
errors=1
  - C19: 呃，嗯。我会考虑在那里多待一天，待到星期天。... (以填充词开头且包含多句，规则在首个句末误切)
saved: /home/yuanwu/notes/reading/slp3/26-conversation-structure/labs/lab-01/out/turn_metrics.json
```

## 结论

1. 简单规则（每个 GOLD 末尾预测一个边界 + 填充词多句时误插边界）在 20 轮上 F1=0.9756，只有 C19 一处失败。
2. C19 的失败模式正是书中说的「人们常常在一个话轮中间停顿」——「呃，嗯。」是话轮内的填充停顿，不是话轮结束。
3. 真实系统的断点检测需要联合声学（停顿时长、语调）与语义（是否说完整）特征，我的时间规则只是下限。

## 反思

我原以为断点检测只是「等多久」的问题，实际跑出来才发现「话轮中间的填充停顿」（呃、嗯）是最大干扰源。人类能区分「思考中的停顿」和「说完了的停顿」，靠的是语义和语调的联合判断，而我的简单规则只看时间。这让我对书中「这项任务可能相当有挑战性」有了具体感受。
