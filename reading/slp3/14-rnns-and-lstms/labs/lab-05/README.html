lab-05 · 编码器-解码器：固定瓶颈 vs 点积注意力（失败案例）

对应 §14.7、§14.8；对应 actions.md 行动 5。这是一个诚实的失败实验：训练指标看起来收敛，评估指标全为 0。

怎么跑

cd labs/lab-05
python3 lab05_encdec_attention.py

无参数，CPU 数十秒。依赖同目录下的 minigrad.py（156 行自写自动微分引擎，支持 matmul / tanh / softmax-CE / 加法 / 逐点乘的 backward）。

输入

项值说明
任务输入序列倒序输出例如 src=[2,4,1,2,2,2] → tgt=[2,2,2,1,4,2]，要求逐位完全正确
符号表SYM=1..5，PAD=0，BOS=6，EOS=7，N_IN=85 个实义符号 + 3 个控制符
模型维度D=24，MAX_LEN=10单层 GRU 风格的编码器与解码器（自写）
训练长度3–8长度 10、12 为未见长度，用于测泛化
两种模式fixed / attnfixed 只用编码器末状态当上下文；attn 每步对全部编码器状态做点积注意力
评估每长度采样 n 条，greedy 解码 max_steps=L+2，逐位比对完全正确率（exact match），不是逐位准确率

唯一可查的完整样例（summary.json 的 attn.example）：

src  = [2, 4, 1, 2, 2, 2]
tgt  = [2, 2, 2, 1, 4, 2]
pred = [2, 2, 2, 1, 4, 2]   ← 预测与目标完全一致

该样例的注意力矩阵呈近似一对一角峰：第 0 步 0.9995 落在 src_pos=5，第 1 步 0.9995 落在 src_pos=4，第 2 步 0.9979 落在 src_pos=3，第 3 步 0.9998 落在 src_pos=2，第 4 步 0.9607 落在 src_pos=1；只有第 5 步分散为 0.4357/0.3303/0.2196（对应 EOS 之后无源位置可对齐）。

结论

  1. 实验未跑通，但模型确实学到了映射：attn 损失降到 0.0141，且被记录的样例 pred 与 tgt 逐位相同、注意力呈完美倒序对齐。这排除了「完全没学会」。
  2. 准确率全 0 与损失矛盾，只可能来自评估口径：greedy 解码在 max_steps=L+2 内可能多吐 EOS/PAD 尾位，导致长度与 tgt 对不上而被判错。这是推断，未验证——我没有加调试打印去核对每个样本的输出长度。
  3. 因此「注意力优于固定瓶颈」在本 lab 中未获数据支持。fixed 的损失（0.48–0.79）明显高于 attn（0.014–0.42），方向上符合预期，但缺少可用的准确率对照，不能写成结论。
  4. attn 训练不稳：step 550 的 0.0141 → step 600 的 0.4163，30 倍反弹。小模型 + 无梯度裁剪 + 固定 lr 是常见成因。

反思

  • 最该被批评的是我没有当场发现矛盾。损失 0.014 配 0% 准确率，本该第一时间触发断言；我把「训练收敛」误当成了「任务成功」，说明验收标准定得太软（只看曲线好不好看）。
  • 修法有两条具体可做：① 评估时截断到第一个 EOS 再比长度，并打印每个样本的 len(pred) vs len(tgt)；② 加早停（连续 3 次验证不降即停）与梯度裁剪，稳住 attn 后期。
  • 这个失败反而生成了一个好题材：spinoffs.md 第 4 篇就是写它——「热图证明了什么、没证明什么」。失败实验的价值在于它把「评估口径」这个隐形前提暴露出来。
  • 不要把它写成「注意力没用」。正确表述是：本实现未能在本任务上给出可用的对照数据。
