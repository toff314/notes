# lab-02 · 手写 BPTT + 梯度校验 + 教师强制的代价

对应 §14.1.2、§14.2.2；对应 `actions.md` 行动 2。

## 怎么跑

```bash
cd labs/lab-02
python3 lab02_bptt_gradcheck.py
```

无参数，纯 numpy 手写前向与反向（**不用**自动微分），CPU 上数秒完成。

## 输入

| 项 | 值 | 说明 |
|---|---|---|
| 语料 | 8 句同构模板句，重复 4 次 | 字符级，词表 V=22 |
| 模型 | d_h=24, d_e=16，参数量 1886 | 单层 Elman 网络 + softmax 输出 |
| 训练 | 120 epoch，全量 BPTT（不截断） | `loss_curve.csv` 每 epoch 一个点 |
| 校验 | W/U/V 的 36 个分量中心差分 | 扰动 eps 按分量尺度取，排除 |grad|<1e-3 的平凡项 |

## 产物（`out/`）

| 文件 | 内容 |
|---|---|
| `grad_check.json` | 损失值、检查分量数、最大绝对/相对误差、反向误差范数逐回溯步的序列 |
| `loss_curve.csv` | 120 行，`epoch,train_loss` |
| `loss_curve.png` | 训练曲线 |
| `teacher_forcing.json` | 教师强制与自由运行两种评估的 loss 与 ppl，含超参与首末轮损失 |

## 关键输出（真实运行）

```
loss = 3.140909
checked_entries = 36      entries_with_abs_grad_gt_1e-3 = 28
max_abs_error = 2.554e-11
max_relative_error_on_nontrivial = 4.272e-09      ← 手写 BPTT 与数值梯度一致
```

反向误差范数（沿时间回溯，10 步）：`1.732 → 0.122 → 0.0168 → 0.00645 → 0.00235 → 8.49e-4 → 3.08e-4 → 1.12e-4 → 4.06e-5 → 1.475e-5`，**每回溯一步掉约一个数量级**——这就是梯度消失的实测形态。

教师强制 vs 自由运行：

| 指标 | 教师强制 | 自由运行 |
|---|---|---|
| loss | 0.0749 | 9.189 |
| ppl | **1.0777** | **9787.49** |

训练过程：首轮 2.4402 → 末轮 0.1224（120 epoch，见 `loss_curve.csv`）。

## 结论

1. **手写 BPTT 是对的**：36 个分量、28 个非平凡项，最大相对误差 4.27e-9，比常见容差 1e-6 还小三数量级。§14.1.2 的「误差项要沿时间累加」在实现上就是那个 `dh_next`，漏掉它会立刻被数值梯度抓住。
2. **梯度沿时间是连乘衰减的**：回溯 10 步，误差范数从 1.73 掉到 1.48e-5，约 5 个数量级；这与 §14.5 描述的机制同向，为 lab-03 的对比提供了解释基础。
3. **教师强制的代价巨大**：同权重、同模型，仅换输入来源，ppl 从 1.08 涨到 9787（约 9000 倍）。训练与推断的输入分布差异不是小瑕疵，而是结构性缺口。

## 反思

- 9787 这个数被语料规模严重放大（164 字符、8 句模板重复 4 次，模型早就背下来了）。**不能**把它当作「真实模型也差这么多」的证据，只能当作「同模型两种跑法的比值」来看。
- 我漏了 planned 的第三组实验：scheduled sampling（逐步用模型输出替代真值），本该验证能否缩小缺口。这条空白已记在 `actions.md` 归因表。
- 校验时我先跑了一次全量 36 项，发现 8 项梯度绝对值 <1e-3（数值上不可靠），才加了 `entries_with_abs_grad_gt_1e-3` 这个过滤。这说明「梯度校验」本身也需要选门槛，不是无脑对拍。
