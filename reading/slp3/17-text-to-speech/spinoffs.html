第 17 章 文本转语音 · 选题衍生（spinoffs）

选题门槛：能独立成文、有一手产物、与本章某节强绑定。状态只有三种：待写 / 在写 / 已发布。

S1　亲手搭一台 8 级残差矢量量化器：残差到底怎么衰减

  • 主题串：矢量量化 / 残差矢量量化 / 码本 / 语音词元化
  • 锚点：§17.2.3「1024 个码字矢量根本不足以表示我们从编码所有可能的语音波形中得到的各种嵌入。」
  • 为什么：书里只说「8 个码字相加」，没给逐级误差曲线；而这条曲线决定了「能不能砍级数换延迟」，是工程上最常被问、最容易糊过去的一个数。
  • 增益：读者拿到可直接运行的 k-means + RVQ 脚本，看到每级 MSE 的实测衰减比，以及「砍到第几级开始听得出糊」的判断依据。
  • 发布：知乎专栏（技术长文）+ 配套仓库
  • 状态：待写（素材已在 labs/lab-02 跑通）
  • 链接：⬜ 待补

S2　「3 秒克隆音色」克隆的究竟是什么

  • 主题串：零样本 TTS / 音色提示 / 说话人嵌入 / 相似度评估
  • 锚点：§17.1「因此，现代 TTS 系统的输入是一段文本提示，或许再加上约 3 秒来自我们希望用以生成语音的那种音色的语音。」
  • 为什么：产品文案把「3 秒」讲成魔法，实际被复制的是音高、共振峰分布与语速习惯的联合统计，而不是某个可命名的「声音指纹」；不讲清这点，用户对「像不像」的预期必然错位。
  • 增益：给出「哪些维度能被 3 秒覆盖、哪些不能」的清单，并把「像不像」拆成可测的说话人相似度得分。
  • 发布：知乎专栏（科普辨析）+ 公众号改写
  • 状态：待写
  • 链接：⬜ 待补

S3　平均意见分的天花板：合成语音评估正在失效

  • 主题串：MOS / CMOS / 成对偏好 / 评估指标设计
  • 锚点：§17.4「我们对比如 50 个句子（以随机顺序呈现）进行这一操作，并比较每个系统被偏好的句子数量。」
  • 为什么：现代系统普遍落在量表上端，系统间差异小于听者间方差，五点量表失去分辨率；而论文仍按老口径报数，读者无法判断「+0.05」有没有意义。
  • 增益：用本章口径 + 一个可复算的偏好统计脚本，说明为什么成对设计在小改动上更灵敏，并给出「多少句才够」的样本量估算。
  • 发布：知乎专栏（方法论）+ 内部分享
  • 状态：待写
  • 链接：⬜ 待补

S4　唤醒词为什么必须待在端侧：一笔隐私账

  • 主题串：唤醒词检测 / 端侧推理 / 语音隐私 / VAD
  • 锚点：§17.5「唤醒词的目标是把检测功能内建到计算边缘的小型设备中，通过将传往云端服务器的用户语音降到最少来保护隐私。」
  • 为什么：这句话在书里只有一行，但它其实是整个语音产品架构的分水岭——一旦音频上行，合规成本与用户信任成本都换代。
  • 增益：把「端侧 vs 云侧」拆成算力、延迟、隐私三条可比较的账，并给出一个 12 秒两说话人音频的切段实验作为最小验证。
  • 发布：知乎专栏（产品向）+ 公众号
  • 状态：待写（素材已在 labs/lab-03 跑通）
  • 链接：⬜ 待补

S5　补一章「口语语言模型」：书稿留白处的五项待填

  • 主题串：口语语言模型 / 统一词表 / 流式生成 / 对话评估
  • 锚点：§17.2「口语语言模型接收文本或语音输入，并能生成文本或语音输出，以解决语音到语音翻译、说话人日志或口语问答之类的任务。」
  • 为什么：§17.6 正文只有「待定」，而这一节恰恰是把 TTS 与 ASR 缝成对话系统的关键；留白处最值得写，因为没有现成叙述可抄。
  • 增益：给出「音频词元化 + 统一词表 + 自回归」的最小可行结构，并列出三项工程参数缺口：训练配比、延迟预算、打断处理。
  • 发布：知乎专栏（综述）+ 读书会讲稿
  • 状态：待写
  • 链接：⬜ 待补
