《Speech and Language Processing》（第 3 版）· 第 17 章 文本转语音 · 读书笔记

本章一句话：现代 TTS 把波形压成每秒几百个离散音频词元，再用「文本词元 + 3 秒音色提示」条件生成这些词元——这等于把「说话」变成了一道语言建模题。

结构：从肯佩伦的机械声道讲到零样本 TTS 的输入输出定义（§17.1）→ 为什么要离散词元、要多粗（§17.2）→ ENCODEC 的编/解码与 320 倍下采样（§17.2.1）→ 矢量量化与码本（§17.2.2）→ 残差矢量量化把一级码本拆成八级（§17.2.3）→ 三种损失与直通估计器（§17.2.4）→ VALL-E 的「一自回归 + 七非自回归」（§17.3）→ MOS/CMOS 评估（§17.4）→ 日志、识别、语种、唤醒词（§17.5）→ 口语语言模型（§17.6，原文待定）→ 小结与历史注记。

可疑处：§17.6「口语语言模型」正文只有一个「待定」，历史注记末尾也写着「编解码器的历史和神经 TTS 的现代史待定」；§17.2.4 式 17.2–17.4 的求和号与分式被抽取过程拆散，我只按上下文重建了结构，不在摘录区引用乱码公式。

与我何干：我做过语音朗读功能，一直把 TTS 当黑盒 API；这一章解释了「为什么音色可以只用 3 秒音频指定」以及「为什么合成质量的天花板由码本和声码器共同决定」——这两点直接决定我怎么给朗读功能定成本与验收口径。

第 17.1 节　TTS 概览：从肯佩伦的机器到零样本　⭐

本节问题：TTS 的输入输出到底是什么？为什么「换一个音色」从「再收几百小时」变成了「再给 3 秒」？

摘录区（原文照抄 + 节号）

  • 「他的装置包括一个模拟肺部的风箱、一个橡胶吹嘴和一个鼻部开口、一个模拟声带的簧片、为擦音准备的各种哨子，以及一个小型辅助风箱用于为塞音提供气流。」（§17）
  • 「文本转语音的任务是生成与目标文本相对应的语音波形，并使用用户指定的特定音色。」（§17.1）
  • 「所得的 TTS 系统只支持一种音色；若想要第二种音色，就得回头去收集第二位说话人的数据。」（§17.1）
  • 「因此，现代 TTS 系统的输入是一段文本提示，或许再加上约 3 秒来自我们希望用以生成语音的那种音色的语音。」（§17.1）
  • 「其思路是取一个庞大的语音数据集，并用一个基于音频编解码器的音频分词器从这些语音中归纳出表示该语音的离散音频词元。」（§17.1）
  • 「编解码器有三个部分：编码器（把语音变为嵌入向量）、量化器（把嵌入变为离散词元）和解码器（把离散词元变回语音）。」（§17.1）

思考区（必须自己的话；【我】开头）

  • 【我】1769 年那台不骗人的机器其实已经把这章的分层摆全了：气源、振动源、可塑的腔体。今天换成文本前端、声学模型、声码器，功能切分没变，只是每一层从手工杠杆换成了学出来的参数。
  • 【我】单人库转向多人库，我认为赢的不是数据量而是接口：过去换嗓音等于重训，现在等于换一段几秒钟的样例。产品侧这相当于把定制成本从周级压到秒级。
  • 【我】零样本这个词我持保留：样例里的说话人确实没在训练集里，可「怎样照着样例模仿」这件事模型是练过的。它更像一段上下文内的复制，而不是真正泛化到没见过的任务。
  • 【我】只有「分词器 + 语言模型」两个部件听起来干净，代价是音色身份被塞进一段提示的隐状态里，失去了显式旋钮。要调语速、情绪、口音，还得再叠加一层条件。

第 17.2 节　为什么要把语音变成离散词元　⭐

本节问题：16 kHz 采样本来就已经离散了，为什么语言模型还是吃不下？「每秒几百个」这个数量级是怎么来的？

摘录区（原文照抄 + 节号）

  • 「现代 TTS 系统的核心思路是把波形转换为离散音频词元的序列。」（§17.2）
  • 「以 16 位格式存储的 16 kHz 语音可以看作由 2^16 = 65,536 个符号构成的一个序列，每秒钟语音对应其中的 16,000 个符号。」（§17.2）
  • 「但一个每秒生成 16,000 个符号的系统会使语音信号过长，语言模型难以实际处理，尤其是基于 Transformer 的模型，其注意力机制具有低效的平方复杂度。」（§17.2）
  • 「我们需要的是代表更长语音片段的符号，大概处于每秒数百个词元的量级。」（§17.2）
  • 「拥有离散词元意味着我们可以利用语言模型技术，因为语言模型专门擅长处理离散词元的序列。」（§17.2）
  • 「τ 通常比 T 小 100–1000 倍。」（§17.2）

思考区（必须自己的话；【我】开头）

  • 【我】采样点这件事提醒我：离散本身不解决问题，问题在时间轴碎到模型吃不下。要压的是时间分辨率，不是数值精度。
  • 【我】平方复杂度这条约束是可以算的：序列从 600 缩到 60，注意力开销掉两个数量级。词元率的选择基本被这条钉死，而不是审美偏好。
  • 【我】压得太狠会丢细节，而丢掉的只能靠后几级码本以残差形式补回来。所以「每秒多少词元」与「每个词元装多少信息」必须成对定，单独调一个必然失衡。
  • 【我】「利用语言模型技术」我原先理解成复用权重，其实重点是复用整套配方：下一个词元预测、温度采样、KV 缓存、批处理推理。

行动区（具体到动作+对象+时间/验收）

  • 本周在 lab-02 里把同一段语音按 16k 采样点、75 帧/秒、600 词元/秒三种粒度算序列长度，并算注意力相对开销（验收：三种粒度的长度与平方开销写入 labs/lab-02/out/summary.json）。

第 17.2.1 节　ENCODEC 的编码器与解码器　⭐

本节问题：24 kHz 波形怎么变成 75 Hz 的嵌入序列？320 倍这个数字意味着多长的一帧？

摘录区（原文照抄 + 节号）

  • 「编码器的目标是把时刻 t 的波形片段（其采样率为 24kHz——一秒语音包含 24,000 个实数值）下采样为 75Hz 的嵌入表示 zt——一秒音频由 75 个向量表示，每个向量的维度为 D。」（§17.2.1）
  • 「由于原始信号以 24kHz 表示，这相当于 24000/75 = 320 倍的下采样。」（§17.2.1）
  • 「其中包含一长串卷积，以及把一次卷积加到先前输入上的残差单元。」（§17.2.1）
  • 「最后，解码器接收量化器输出的嵌入 zqt，并通过一组对称的卷积网络对音频进行上采样，生成波形。」（§17.2.1）
  • 「维度为 D = 256 的向量 zt，将其量化为离散符号 qt，再把它变回维度为 D = 256 的向量 zqt，然后解码／上采样该向量，还原为 24kHz 的波形。」（§17.2.1）

思考区（必须自己的话；【我】开头）

  • 【我】320 这个倍数我一直当超参看，其实它等价于「一帧 13.3 毫秒」。这个尺度刚好落在音素转换的量级上：更密就是在描述波形，更疏就跨过了整个音段。
  • 【我】编码解码对称有个隐性代价：解码端要从 256 个数重建 320 个采样点，编码阶段丢掉的任何东西都会在这一步被放大成能听见的噪声。
  • 【我】这里的残差连接不只是常规的防梯度消失，它让下采样网络可以主动跳过细节，把细节留给后面的量化级去补。
  • 【我】我原以为声码器是独立模块，读完这段才把它并进解码器：上采样和波形重建在这里是同一件事，边界被架构吃掉了。

第 17.2.2 节　矢量量化与码本　⭐

本节问题：把一串浮点向量换成整数索引，具体怎么换？k-means 在这里扮演什么角色？

摘录区（原文照抄 + 节号）

  • 「为了压缩语音的向量表示序列，我们把每个向量转成一个整数，即代表某个类别或簇的索引。」（§17.2.2）
  • 「因为 VQ 能方便地产生离散词元，而这些词元与语言建模范式非常契合，因为语言模型很擅长预测离散词元的序列。」（§17.2.2）
  • 「然后把这 N 个向量聚成 k 个簇；k 由设计者作为算法参数设定，表示我们想要的离散符号数量，通常有 k << N。」（§17.2.2）
  • 「在分配步骤中，给定 k 个当前质心和整个矢量数据集，每个矢量被分配到其码字最接近（按平方欧氏距离）的那个聚类。」（§17.2.2）
  • 「我们把聚类 id（词元）的列表连同其码字一起称为码本，并常把聚类 id 称为码。」（§17.2.2）
  • 「码字矢量不会与输入语音段的原始矢量编码完全一致，尤其是在只有 1024 个可能码字的情况下；但如果码本足够好，我们希望它至少是接近的，解码器仍能产生合理的语音。」（§17.2.2）

思考区（必须自己的话；【我】开头）

  • 【我】同一套聚类算法，在压缩语境里服务比特率，在生成语境里服务「可被采样」——目标函数换了，代码可以一行不改。这是我见过的最省事的复用。
  • 【我】簇数是分辨率与词表大小的交换：簇越多，单个符号装的信息越细，但语言模型要预测的类别变多，长尾符号的样本也越少。
  • 【我】码本本质是一张查表，表外的向量永远只能近似。lab-02 想看的是近似误差随簇数变化的曲线，而不是一个孤零零的最终数值。
  • 【我】推理端只做最近邻，复杂度是「簇数 × 维度」，全流程最便宜。但它也最脆：一旦码本里有重复或死簇，模型就会学到两个无法区分的符号。

行动区（具体到动作+对象+时间/验收）

  • 在 lab-02 中把码本大小从 8 扫到 256，逐档记录重构误差与码字使用率（验收：≥4 个档位，每档都输出未使用码字比例，写入 CSV）。

第 17.2.3 节　残差矢量量化　⭐

本节问题：1024 个码字不够用，是把码本做大，还是换一种组织方式？

摘录区（原文照抄 + 节号）

  • 「在实践中，简单 VQ 产生的重建结果不够好，至少在码本大小为 1024 时如此。」（§17.2.3）
  • 「1024 个码字矢量根本不足以表示我们从编码所有可能的语音波形中得到的各种嵌入。」（§17.2.3）
  • 「残差有点像舍入误差；这就好比在 VQ 中我们把矢量“舍入”到最近的码字，从而产生了某种误差。」（§17.2.3）
  • 「这样我们得到第二个码字，用来表示矢量中残差的那部分。」（§17.2.3）
  • 「最终结果是 8 个码字（原始码字加上 7 个残差）。」（§17.2.3）
  • 「在 ENCODEC RVQ 中同样简单：我们取出这 8 个码字并把它们相加！」（§17.2.3）

思考区（必须自己的话；【我】开头）

  • 【我】把「1024 个词」「换成」「8 组各 1024 个词」，组合空间是天文数字，但每级只需在 1024 里选一次，代价随级数线性增长。这是我在这章里最欣赏的设计。
  • 【我】逐级补残差带出一个副产品：第一级承载粗粒度内容，后面几级只补细节。VALL-E 敢只用自回归跑第一级，靠的就是这个现成的层级。
  • 【我】我猜残差量级会逐级指数衰减，lab-02 会给出每级的误差比。若某一级几乎不降，那是训练故障（码本没学满），不是架构到头。
  • 【我】重建只是把码字相加，这一步没有任何可学习参数，于是「相加后仍不像」的全部差距都得由解码器承担——声码器才是真正的短板。

第 17.2.4 节　训练词元化器：三种损失与直通估计　🔴

本节问题：量化步骤不可微，梯度怎么穿过去？三个损失各管什么？权重怎么定？

摘录区（原文照抄 + 节号）

  • 「期望的输出是同一个波形段，因为该模型是一种学习映射到自身的自编码器。」（§17.2.4）
  • 「该模型在大规模语音数据集上训练完成这种重建，例如 Common Voice（Ardila et al., 2020）（133 种语言、超过 30,000 小时的语音）」（§17.2.4）
  • 「重构损失 Lreconstruction 衡量输出波形与输入波形的相似程度，例如通过原始音频与重构音频之间的平方和差值来度量：」（§17.2.4）
  • 「首先，在反向传播中忽略量化步骤。取而代之，我们把梯度从量化器的输出（zqt）直接复制回量化器的输入（zt），这种方法称为直通估计器（straight-through estimator）（Van Den Oord et al., 2017）。」（§17.2.4）
  • 「一种方法是先使用 k-means 对向量 zt 进行聚类，得到初始的聚类。」（§17.2.4）
  • 「于是，总损失函数可以简单地为这些损失的加权和：」（§17.2.4）

思考区（必须自己的话；【我】开头）

  • 【我】对不可导的取整操作直接搬用上游梯度，数学上不成立，工程上却有效。承认它是有偏估计比包装成推导更诚实，也更能解释它为什么偶尔训练崩。
  • 【我】三个损失分工清楚：一个对齐波形、一个管听感逼真、一个防止码字塌缩。真正没有答案的是权重，书里只给了符号，而这恰恰是复现的分水岭。
  • 【我】对抗项让我警惕：判别器一强，重建项的梯度就被压制，容易出现「听着像、内容不对」。MOS 高而 WER 高的系统多半死在这里。
  • 【我】先用聚类定初值、再用在线均值维护，这套做法在 lab-02 里可验：初值差的码本会出现大量空簇，第一级残差几乎不下降。

  • 本周在 lab-02 中用两种码本初始化（随机取样 vs k-means++ 式最远点）各跑一次，比较空簇数与首级残差（验收：两组空簇数与首级 MSE 写入 labs/lab-02/out/summary.json）。

第 17.3 节　VALL-E 的两阶段语言模型　⭐

本节问题：一次自回归能不能生成全部 8 级编码？为什么要拆成一自回归加七非自回归？

摘录区（原文照抄 + 节号）

  • 「VALL-E 没有用单个自回归语言模型来完成这种条件生成，而是使用两个不同的语言模型，通过两阶段过程进行条件生成。」（§17.3）
  • 「第一个 RVQ 量化器的输出是对最终语音最重要的词元，而后续量化器向最终信号贡献的残差信息越来越少。」（§17.3）
  • 「首先，一个自回归语言模型在给定输入文本与注册音频的情况下，为整个输出序列生成第一个量化器的编码。」（§17.3）
  • 「然后，在给定这些编码的情况下，一个非自回归语言模型被运行 7 次，每次以初始自回归编码的输出以及前一个非自回归量化器的输出作为输入，从而逐个生成其余量化器的编码。」（§17.3）
  • 「在推理阶段，给定一段待朗读的文本序列以及 y′，即来自某个未见说话人的注册语音样本，我们拥有它的转写 transcript(y′)。」（§17.3）
  • 「首先把 3 秒注册语音的转写前置到待生成的文本之前，并对语音和文本分别进行分词。」（§17.3）

思考区（必须自己的话；【我】开头）

  • 【我】把八级拆成一次慢生成加七次快补全，是用架构去贴合数据本身的层级，而不是让一个模型硬啃所有层。结构先验在这里赢过堆容量。
  • 【我】推理时把样例的转写拼到待读文本前面，这招很巧：模型看到的是一段连续文字，身份信息交给声学提示，文字内容交给位置，两个条件互不打架。
  • 【我】时序连贯性主要由粗层负责，所以只有第一级需要逐帧自回归；后七级被当成细节补全，可以并行、可以看整段上下文。
  • 【我】风险也在这儿：第一级一旦跑偏（漏字、重复、拖长），后七级只会忠实地替它上色，错误无法回退。这跟 ASR 里自回归解码的失败模式是同一类。

第 17.4 节　MOS 与 CMOS：怎么给合成语音打分　🔵

本节问题：合成语音「好不好」怎么量化？为什么两个指标不能互相替代？

摘录区（原文照抄 + 节号）

  • 「随后，我们可以通过比较各系统在相同句子上的 MOS 得分来比较它们（例如使用配对 t 检验来检验是否存在显著差异）。」（§17.4）
  • 「CMOS 得分的范围从 -3（该系统比参考系统差得多）到 3（该系统优于参考系统）。」（§17.4）
  • 「这里我们播放由两个不同系统合成的同一个句子。」（§17.4）
  • 「我们对比如 50 个句子（以随机顺序呈现）进行这一操作，并比较每个系统被偏好的句子数量。」（§17.4）
  • 「例如，我们可以把输出送入 ASR 系统并计算词错误率（WER），以考察合成输出的稳健程度。」（§17.4）
  • 「或者，为了衡量 TTS 系统的语音输出与注册语音的匹配程度，我们可以把该任务当作说话人验证来处理：将两个语音送入说话人验证系统，并把得到的得分用作相似度得分。」（§17.4）

思考区（必须自己的话；【我】开头）

  • 【我】五分钟量表最容易撞天花板：现在的系统普遍 4.2 往上，区分度只剩小数点后一位，而听者之间的方差往往比系统之间的差还大。
  • 【我】配对设计是这套方法的地基，同一句话的难度差异远大于系统差异。不做配对，等于拿噪声当信号。
  • 【我】成对偏好只回答「哪个更顺耳」，不回答「好了多少」。所以两者是分工：迭代筛小改动用偏好，对外报绝对水平用平均分。
  • 【我】拿识别错误率当代理指标有方向性陷阱：识别器越宽容，合成端的毛病越藏得住。要用就必须锁死同一个识别器版本并公开。

  • 「大多数早期 TTS 系统使用音素作为输入；TTS 的文本分析组件发展得稍晚一些，借鉴了 NLP。」（§历史注记）
  • 「编解码器的历史和神经 TTS 的现代史待定。」（§历史注记）

  • 【我】三条老路线都没死：共振峰法在可解释的参数化声码器里活着，拼接演化成单元选择乃至今天的码本检索，发音合成退到教学与研究。
  • 【我】单元选择讲的「目标代价」其实就是检索式 TTS：从大库里挑最像的片段。神经方法把库换成了码本，把代价换成交叉熵。

  • 【我】我的判断是：这行的核心问题已经从「听不听得懂」变成「像不像这个人」，而后者正是平均分与说话人相似度两个指标在争的地盘。

全章 takeaway（5 条）

  1. TTS 的现代形态是「条件语言建模」：文本词元 + 音色提示 → 音频词元，音色由提示决定而非权重决定。
  2. 音频必须被压到每秒数百个词元，理由是注意力开销与序列长度，而不是存储。
  3. 矢量量化把连续嵌入换成码本索引；单个码本不够时用残差逐级补，八级相加还原。
  4. 量化不可微，靠直通估计器把梯度原样搬回去；码本靠聚类初值 + 在线均值维护。
  5. 评估以人的平均分为主、成对偏好为辅，自动指标只能做补充。
