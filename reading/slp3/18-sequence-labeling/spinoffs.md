### 1. 为什么你的 NER 模型词元准确率 95%，实体 F1 却只有 85%

- **交付给**：`write-zhihu-tech`（Mode A）
- **主题串（可直接复制）**：`观点：NER 评估的两个口径为什么差这么多——从一次边界错记两笔账说起`
- **书籍锚点**：《Speech and Language Processing》第 3 版 §18.6「对于命名实体标注而言，响应单元是实体，而不是词」；「一个系统若把 Jane 而非 Jane Villanueva 标为人名，就会造成两个错误：一个针对 O 的假正例和一个针对 I-PER 的假负例」。
- **为什么**：命中 **S1 + S3 + S5** —— ①S1：书中只给结论与一句话例子，没给完整代码与量化对照；②S3：涉及 BIO 解码、span 匹配、P/R/F1 计算、错误归因四步，有足够纵深；③S5：所有做信息抽取、知识图谱、搜索结构化的人都被这个问题折磨过，直接决定业务方对模型的信任度。
- **增益**：① 相对本书：用 lab-03 的三组对照（A_short/B_long/C_type）把「切短」「切长」「类型错」三类错误的词元级与实体级惩罚并排展示，让读者看见 F1 与 token accuracy 之间那条常年 5–8 个点的鸿沟从哪来；② 对读者：给出一份可执行的「NER 评估检查清单」，避免只看 token accuracy 就上线的悲剧。
- **素材种子**：历史溯源 {MUC-6 评测开始要求实体级匹配}｜人物 {Hovy、Chinchor、Tjong Kim Sang}｜原理 {BIO 解码、span 匹配、边界错误的非线性惩罚}｜争议 {F1 对「切短」与「切长」完全对称，是否该用更细粒度的指标}
- **缺口（下游必须自己搜）**：CONLL-2003 上典型系统的 token accuracy vs entity F1 对照数据；医学 NER 中边界错误的具体分布统计。
- **体量建议**：标准长文（现象 → 机制 → 我的三组实验 → 评估检查清单 → 进阶：该不该用 softer metrics）
- **待核**：❓ 我的三组案例只有 20 个词元、8 个实体，统计意义为零；正文必须注明这是机制演示而非效果结论。

### 2. HMM 是 CRF 的特例：一次可复现的等价性实验

- **交付给**：`write-tech-tutorial`（Mode A）
- **主题串（可直接复制）**：`论文：把 HMM 塞进 CRF 的权重里——生成式与判别式模型的等价性实验`
- **书籍锚点**：§18.5「CRF 是一种对数线性模型：在给定整个输入（词）序列 X 的条件下，它为所有可能的序列 Y 中的某个完整输出（标记）序列 Y 分配一个概率」；§18.5.3「我们将转向维特比算法；它之所以可行，是因为与 HMM 一样，线性链 CRF 在每个时间步只依赖于前一个输出词元 yi−1」。
- **为什么**：命中 **S1 + S3 + S6** —— ①S1：书中只给一句「HMM 能写成 CRF 的特例」，没给完整实现与验证代码；②S3：涉及 log 空间转换、特征模板设计、前向-后向训练、维特比解码四步，有足够纵深；③S6：Lafferty et al. 2001、Sutton & McCallum 2011、Jurafsky & Martin 第 18 章均可查。
- **增益**：① 相对本书：把「HMM 是 CRF 的特例」这一结论落成可运行代码（我的 lab-02，同一份维特比、同一条路径、同一个分数），并解释为什么「等价」要求标签集、起始项、特征定义三者同时对齐；② 对读者：拿到一份能跑通、并知道每一步为什么的教程，而不是被「生成式 vs 判别式」的口号式对比糊弄。
- **素材种子**：历史溯源 {Lafferty 2001 提出 CRF；Ratnaparkhi 1996 的 MXPOST 是 MEMM}｜人物 {Lafferty、McCallum、Sutton、Ratnaparkhi}｜原理 {对数线性模型、softmax 归一化、前向-后向}｜争议 {MEMM 的标签偏置问题}
- **缺口（下游必须自己搜）**：Lafferty 2001 原始论文中的实验设置；MEMM 标签偏置问题的具体例子；CRF++ 与 sklearn-crfsuite 的实现差异。
- **体量建议**：教程（环境 → HMM 三件套 → CRF 特征模板 → 等价性转换 → 实验验证 → 调参陷阱）
- **待核**：❓ 我的 lab-02 用 7 句训练语料、5 个标签，只证明机制成立；正文需注明真实规模下的特征空间是十万量级。

### 4. 规则先跑、模型后接：工业界 NER 为什么还没抛弃正则

- **主题串（可直接复制）**：`观点：工业界 NER 为什么还在用正则——规则与模型的四步流水线`
- **书籍锚点**：§18.7.1「尽管机器学习的（神经或 CRF）序列模型是学术研究中的常规做法，但商业 NER 方法往往建立在列表与规则的务实组合之上，只辅以少量有监督机器学习（Chiticariu et al., 2013）」；「首先，使用高精确率的规则来标注无歧义的实体提及。然后，搜索先前检测到的名称的子串匹配。使用特定应用的名词列表来找出可能是领域特定的提及。最后，应用有监督序列标注技术，把前面几个阶段产生的标记作为额外特征使用」。

- **增益**：① 相对本书：把书中一段四步描述扩展成可运行的流水线代码，并用 lab-02 的 CRF 当最后一级，量化「规则省样本」的具体收益；② 对读者：给出一套「什么时候该上规则、什么时候该上模型」的决策框架，而不是非此即彼的站队。
- **素材种子**：历史溯源 {Klein & Simmons 1963 的两阶段架构；Church 1988 的 PARTS}｜人物 {Chiticariu、Karlsson、Voutilainen}｜原理 {高精确率规则、子串匹配、词典特征}｜争议 {规则的可维护性 vs 模型的可解释性}
- **缺口（下游必须自己搜）**：IBM System T 的实际应用案例与性能数字；金融领域 NER 中规则与模型的混合比例调查。
