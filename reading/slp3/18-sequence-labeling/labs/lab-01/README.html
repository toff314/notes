lab-01　用手算网格复现 HMM 维特比

怎么跑 / 方法

cd labs/lab-01 && python3 run_viterbi.py
  1. 把图 18.12 的 A 表（8×7，首行 <s> 单列为 π）与图 18.13 的 B 表（7×5）抄成 numpy 数组。
  2. 全部转 log 空间，用向量化 V[t-1] + logA[:, j] 填格；分数矩阵 V 与回溯指针 bp 分开存，指针在取 argmax 的同一刻落下。
  3. 从末列 argmax 起回溯，得到路径；同时算两个基线：全标 NNP、逐词取 B 表最大标签（MFT）。
  4. 落盘 out/viterbi_grid.csv（含每格的 log 分数与每列指针）、out/path.txt、out/checks.json。

依赖：python3 + numpy。

关键输出 / 结果

gold    : Janet/NNP will/MD back/VB the/DT bill/NN
viterbi : Janet/NNP will/MD back/VB the/DT bill/NN    ← 与书中一致
MFT基线 : Janet/NNP will/MD back/RB the/DT bill/NN    ← 只有 back 错
指标数值
解码路径NNP MD VB DT NN（= 金标准，5/5）
整句 log 分数−33.8389，即 P = 2.0136e-15
will 列 MD 格3.0041e-8，书中为 2.772e-8，相对偏差 8.4%
基线「全标 NNP」1/5 = 0.20
基线「逐词取最大发射」4/5 = 0.80
七行行和NN 0.183、RB 0.352、VB 0.457、NNP 0.468、JJ 0.569、DT 0.819、MD 0.973

结论

  • 维特比在 8×5 网格上用 5 步就还原了金标准路径，且只看路径不看分数会漏掉 bug：整句概率 2e-15 与书中 2.772e-8 差七个数量级，因为后者是「will 列 MD 格」的值，不是句子的联合概率。两者不能混为一谈。
  • 8.4% 的偏差无法用浮点误差解释。B 表只给到 6 位小数（0.000032），而书中 2.772e-8 显然来自未四舍五入的原始计数；用四舍五入表复算必然落在 3.0e-8 附近。书中的范例数值不能当单元测试的精确期望值，只能当量级校验。
  • 图 18.12 的七行行和从 0.18 到 0.97 不等，没有一行等于 1。这张表是从完整 UD/PTB 标记集中切出的 7 标签子集，列也被裁过，所以它演示的是「怎么算」，不是「真实概率」。若拿它当概率做置信度，会系统性低估。
  • MFT 基线 0.8 已经离 HMM 只差一个词（back 的 RB/VB 之争），印证 §18.2 的「92% 傻瓜基线」：任务的绝对提升空间本来就很薄。

反思

  • 我第一次写维特比犯的错正是「先填完分数再回头找前驱」。当某列出现并列最大值（本例 back 列的 RB 与 VB 只差 0.02 个 log 单位）时，事后搜索会挑到与指针不一致的前驱，路径悄悄变错而分数不变。指针必须在当场记。
  • log 空间不是可选项：整句概率 2e-15 尚在 float64 范围内，但换成 30 词的句子就会下溢成 0，一旦为 0，所有路径并列，argmax 变成「全取第一个标签」。这是我最容易在生产里翻车的地方。
  • 行和不为 1 这件事，我是写完校验才发现。如果早一点加断言，我会更早意识到「书的示例表 = 节选」这个前提，而不是先怀疑自己抄错了行列表头（图的表头是「条件事件」，行列极易读反）。
