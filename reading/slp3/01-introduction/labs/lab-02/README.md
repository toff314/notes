# Lab 02　困惑度与平滑：加一平滑真的能救 bigram 吗？

**对应行动**：actions.md 第 2 条
**书中锚点**：§1.9.2 词预测准确率、§1.6.1 预训练目标
**脚本**：`perplexity.py`　**产物**：`out/perplexity.json`、`out/perplexity.csv`、`out/perplexity.png`

## 输入与设置

- 训练语料同 Lab 01（13,116 token，词表 2,381）。
- 测试句：`so long and thanks for all the fish`（书中 §1.9.2 的例子）。
- 该句在训练前整句剔除；`thanks`、`fish` 都是训练集 OOV。
- 困惑度：`PP = exp(-(1/N) Σ ln p(w_i | context))`，N=8。

## 运行

```bash
cd labs/lab-02
python3 perplexity.py
```

## 关键输出（真实运行）

| 模型 | 困惑度 |
|---|---|
| unigram 无平滑 | ∞（OOV 概率 0） |
| unigram 加一 | 552.02 |
| bigram 无平滑 | ∞（存在零转移） |
| bigram 加一（k=1） | 1292.76 |
| bigram 加 k（k=0.0001） | 3572.58 |
| bigram 加 k（k=0.001） | 1572.26 |
| bigram 加 k（k=0.01） | 877.79 |
| bigram 加 k（k=0.1） | 846.86 |

## 结论（引用自己的产物）

1. 不平滑的两种模型都直接爆成 ∞：只要测试句里有一个未见词或一个未见转移，
   连乘就归零。**困惑度对零概率极其敏感。**
2. 加一平滑把 bigram 救到 1292.76，但同条件下 unigram 加一只有 552.02——
   bigram 反而更差。原因是词表 2,381，加一给每个上下文都摊了 2,381 个伪计数，
   而语料只有 1.3 万 token，稀疏性把平滑变成了"过度抹平"。
3. k 从 0.0001 调到 0.1，困惑度从 3572 降到 847；再调到 1（等于加一）又回升到 1293。
   存在一个中间最优点，**平滑强度本身是要调的参数**，不是"加上就完事"。
4. 这组数字不能拿去和书里的 LLM 比：词表、测试集、分词口径都不同。
   困惑度只在**同一词表、同一测试集**下可比。

## 反思

我原来把"加一平滑"当成万能补丁，觉得只要不出现零概率就赢了。实测 bigram 加一
比 unigram 加一还差，才理解平滑是在用"给未见事件留预算"换"已见事件的概率质量"，
预算大小取决于词表和语料规模。书里说困惑度"对长度归一化"，但没说的是：
它同时对词表大小和 OOV 口径高度敏感。
