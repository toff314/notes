lab-02　加窗与 DFT：矩形窗 vs 汉明窗的泄漏代价

对应 actions.md 第 2 条；对应书中 §15.5.1（采样）、§15.5.2（加窗）、§15.5.3（DFT）。

怎么跑

cd labs/lab-02
python3 window_dft.py

无参数；常数内置：FS=16000、FRAME=400（25 ms）、STRIDE=160（10 ms）、NFFT=512（频率分辨率 31.25 Hz/bin）。

输入

  • 两个合成纯音：240 Hz 与 250 Hz，时长 0.5 s，各取 48 帧。
  • 一个三段共振峰合成的 [ae]（F1/F2/F3 = 930/1860/3020 Hz，书中 §15.4.5 的实测值），用于看谐波对比度。

产物

文件内容
out/windowing_metrics.csv两种窗在 240/250 Hz 下的扇贝损失、3 dB 主瓣宽、主瓣外能量占比、最坏旁瓣
out/window_leakage.png矩形/汉明窗的频谱对照（对数幅度）
out/vowel_ae_spectrum.png[ae] 的加窗频谱与三个共振峰标注
out/summary.json上述指标 + 谐波对比度

关键输出（真实运行）

240 Hz（帧内 6.0 个周期）：

指标矩形窗汉明窗
扇贝损失−1.09 dB−0.45 dB
3 dB 主瓣宽31.25 Hz62.5 Hz
主瓣外能量占比4.2%0.03%
最坏旁瓣−17.96 dB−37.45 dB

250 Hz（帧内 6.25 个周期）：矩形 −18.45 dB 旁瓣 / 5.13% 泄漏，汉明 −43.11 dB / 0.04%。

[ae] 谐波对比度（最强与最弱谐波之差）：矩形 12.25 dB，汉明 6.27 dB。

结论

  1. 加窗买到的是动态范围：旁瓣从 −18 dB 压到 −43 dB，主瓣外能量从 4–5% 降到 0.03–0.04%，于是弱谐波不会被强峰的裙边淹没。代价是频率分辨率：3 dB 主瓣从 31.25 Hz 宽到 62.5 Hz（正好等于两个 bin）。
  2. 汉明窗的谐波对比度反而更低（6.27 vs 12.25 dB），说明它把能量摊得更开——这不是缺陷，而是「用分辨率换泄漏」的同一枚硬币。
  3. 240 Hz 与 250 Hz 的差别揭示扇贝损失（scalloping loss）：纯音落在 bin 中心时矩形窗几乎无损失（−0.02 dB），落在两 bin 之间时损失 1.09 dB；汉明窗把这个波动压到 0.45 dB 以内，所以对「音高会漂」的真实语音更稳。

反思

  • 与书对照：书中只说矩形窗「会在其边界处突然截断信号，这在我们做傅里叶分析时会带来问题」，没给数值；本 lab 把这句定性话变成了 −18 → −43 dB 的定量差距。
  • 我原来的误解：以为汉明窗「更准」。实测恰恰相反——它的主瓣更宽，频率定位更糊；它赢在旁瓣。所以「用哪个窗」取决于你要分辨两个靠近的峰，还是要看见一个很弱的峰。
  • 没做好的：只测了 240/250 Hz 两个频率，扇贝损失随频率与帧长的关系没有扫；48 帧里也只用了单帧指标。
  • 可延展：把 NFFT 从 512 提到 1024，主瓣宽会减半、旁瓣不变——这条对照能直接支撑 spinoffs 选题 2 的「nfft 怎么选」一节。
