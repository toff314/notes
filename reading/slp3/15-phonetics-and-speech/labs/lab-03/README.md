# lab-03　梅尔滤波器组：把 257 个频点压成 80 维，再验噪声下的稳健性

对应 `actions.md` 第 3 条；对应书中 §15.4.3（音高感知）、§15.5.4（梅尔滤波器组与对数）。

## 怎么跑

```bash
cd labs/lab-03
python3 mel_filterbank.py
```

无参数；常数内置：`FS=16000`、`FRAME=400`、`STRIDE=160`、`NFFT=512`（31.25 Hz/bin）、`NCH=80`。

## 输入

- 合成的 4 个元音类（各自由三共振峰谐振器生成），每类 20 次试验；
- 噪声按信噪比 20 / 10 / 0 / −5 dB 四档加入。

## 产物

| 文件 | 内容 |
|---|---|
| `out/mel_scale.csv` | 每 100 Hz 对应的梅尔增量（刻度非线性证据） |
| `out/filterbank.png` | 80 个三角滤波器的形状与中心频率分布 |
| `out/snr_sweep.csv` | 四档 SNR 下三种特征的分类准确率 |
| `out/logmel_predict_clean.csv`、`out/logmel_predict_snr10.csv` | 逐条预测记录 |
| `out/summary.json` | 通道数、频点分配、SNR 扫描、边界余量 |

## 关键输出（真实运行）

- 80 通道覆盖的中心频率 **22.1 Hz → 7733.5 Hz**；每个滤波器覆盖的 bin 数从**第一个 1 个**到**最后一个 16 个**。
- 刻度非线性：0–100 Hz 一段得 **150.5 mel**；700–800 Hz 只得 **77.8 mel**；7000–7100 Hz 只剩 **14.5 mel**——同样 100 Hz，低频的信息密度是高频的十倍。
- SNR 扫描（4 类元音分类准确率）：

| SNR | 对数梅尔 80 | 线性 80 | 线性 40 |
|---|---|---|---|
| 20 dB | 1.000 | 1.000 | 1.000 |
| 10 dB | 1.000 | 1.000 | 1.000 |
| 0 dB | 1.000 | 1.000 | 0.978 |
| −5 dB | 0.889 | 0.889 | 0.844 |

- 类间边界余量：对数梅尔 4.78、线性 80 维 6.25、线性 40 维 5.21。

## 结论

1. 梅尔刻度确实把频率轴「低频拉开、高频压缩」：1 个 bin（31.25 Hz）在低频几乎独占一个滤波器，在高频要和 16 个 bin 一起挤进一个滤波器。这就是「高频分辨率低」的准确含义——不是听不见，是分辨不出。
2. 80 通道的三角滤波器在 7.7 kHz 处仍留有覆盖，说明上截止不是简单截到 4 kHz；但 4 kHz 以上的能量对元音区分贡献很小，这也解释了电话带宽为何够用。
3. **对数压缩的收益没有我预期的大**：−5 dB 时对数梅尔 0.889 与线性 80 维 0.889 完全持平，只比线性 40 维（0.844）好。原因很可能是本 lab 的噪声是加性白噪、且分类器基于欧氏距离——对数的真正优势（把通道增益变成加性偏置）需要乘性信道或跨说话人增益差异才能显现。

## 反思

- **最值得记的一条**：不要因为「书上是这么写的」就假定对数一定更好；在同分布白噪下它只是不更差。这直接改写了 actions.md 第 3 条的验收口径（原写「对数更稳」，实测只能写「不低于」）。
- **设计缺陷**：4 类元音 × 20 次试验、单一分类器、纯加性噪声，样本与噪声模型都太窄；`margin` 三个数（4.78/6.25/5.21）还互相矛盾——余量最大的线性 80 维在 −5 dB 反而与对数梅尔持平，说明「余量」这个指标本身不预测噪声稳健性。
- **没做**：没有做乘性信道（卷积噪声）实验，而那才是 MFCC 对数压缩的主场；也没有比较 fbank 与 MFCC 在下游分类器上的差异。
- **与 spinoffs 的关系**：选题 4（梅尔刻度）可以直接用 150.5 / 77.8 / 14.5 这组数字做开头，它比任何比喻都能说明「耳朵不是频谱仪」。
