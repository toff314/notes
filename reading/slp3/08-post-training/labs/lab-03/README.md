# lab-03：best-of-N 的收益上限与奖励噪声

**对应**：§8.3.3（奖励模型的 best-of-N 用途）、§8.4（学到的奖励只是真实奖励的带噪替代）。
**行动**：`actions.md` 第 3 条。

## 目的

量化一个工程直觉：**增大候选数 N 是否总能挑到更好的回答？** 把奖励模型写成「真实质量 + 噪声」，测量三个量随 N 与噪声 σ 的变化：

1. 被选中候选的**期望真实质量** `E[z_sel]`；
2. **选中真最优候选的概率** `P(z_sel = max z)`；
3. **奖励高估** `E[r_sel − z_sel]`，即奖励模型给选中项的分数比它的真实质量高多少。

## 输入

- 无外部数据，全部蒙特卡洛模拟，`numpy.random.default_rng(11)`。
- 每个提示采样 N 个候选，真实质量 `z ~ N(0,1)`；奖励模型打分 `r = z + ε`，`ε ~ N(0, σ²)`。
- `N ∈ {1,2,4,8,16,32,64,128}`，`σ ∈ {0, 0.25, 0.5, 1.0, 2.0}`，每个 (σ,N) 组合 4,000 次试验（每次批量 8 个提示以控制内存）。
- 按 `argmax r` 选一个候选，记录它的 `z`、`r` 与是否等于该组真实最大值。

## 运行

```bash
cd labs/lab-03
python3 best_of_n.py
```

只依赖 numpy 2.4.6 + matplotlib 3.10.9；随机种子固定。本次运行退出码 0。

## 结论

1. **无噪声时，N 越大严格越好。** σ=0 时 P(选中真最优) 恒为 1，期望真实质量从 N=1 的 0.006 单调升到 N=128 的 2.599；这是极值统计的教科书结果。
2. **有噪声时，期望真实质量仍随 N 上升，但增速被 σ 压住。** σ=0.5、N=2→128，质量从 0.507 升到 2.332；σ=2 时只从 0.246 升到 1.150。噪声把"多采样"的边际收益越吃越少。
3. **P(选中真最优) 反而随 N 下降。** σ=0.5 时从 N=2 的 0.853 降到 N=128 的 0.460；σ=2 时从 0.652 降到 0.082。N 越大，取最大值的样本越多，最大值越可能落在"噪声高"而不是"质量高"的候选上。
4. **奖励高估随 N 与 σ 放大。** σ=2、N=128 时平均高估 4.657——奖励模型给选中项的分远高于它的真实质量。因此 best-of-N 上线前必须同时看"真实质量"和"奖励高估"，只看奖励分数会系统性乐观。

## 局限

- 真实质量与奖励噪声都假设为**独立同分布高斯**；真实 RM 的误差随提示、长度、领域变化，且与质量相关。
- 所有提示共享同一分布，没有提示难度分层；难提示上的选择偏差可能更严重。
- 真实 best-of-N 还要付 N 倍采样与打分成本，本实验没有建成本模型。
- 4,000 次试验对概率的估计有蒙特卡洛误差（约 ±0.01–0.02），趋势可信，小数点后第二位不宜过度解读。
- 「真最优」定义为该组 N 个候选中的最大值，不是全局最优回答；它衡量的是选择效率，不是绝对质量。

## 反思

我原来以为 N 越大越接近"最优"，最多是收益递减。实验给出的反例更尖锐：σ=0.5 时，N 从 2 增到 128，被选中答案的平均真实质量确实从 0.51 升到 2.33，但"它是不是这 N 个里最好的"这一概率却从 0.85 掉到 0.46。两件事并不矛盾——极值让平均质量上升，噪声让"选中最大值"更容易被错误候选占据。

这改变了我看 best-of-N 的方式：它是一个**用算力换质量、同时用选择偏差换奖励高估**的交易。上线前该问的不是"N 能开多大"，而是"奖励噪声有多大、我能不能承受它带来的高估"。
