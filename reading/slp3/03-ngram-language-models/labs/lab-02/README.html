lab-02：四种平滑方法的困惑度对比

目的

对应 actions.md 第 2 条：在同一 trigram 测试集上比较 MLE、拉普拉斯、加 k、Jelinek-Mercer 插值、愚蠢回退，验证书 §3.6 的定性判断。

方法

  • 语料与切分同 lab-01（../shared_corpus.py，seed=7）。
  • 模型：trigram；词表 68 个（含 <unk>）。
  • 平滑：
  • MLE：C(ctx,w)/C(ctx)，未见 trigram 概率为 0；
  • 拉普拉斯：k=1；
  • 加 k：k=0.1 / 0.01 / 0.001；
  • 插值：λ1·P_uni + λ2·P_bi + λ3·P_tri，在 dev 上以 0.05 为步长网格搜索，最大化对数似然；
  • 愚蠢回退：λ=0.4，逐级回退到 unigram，不归一化。
  • 指标：测试集逐 token 困惑度；愚蠢回退只能算"伪困惑度"（分数非概率）。

运行

python3 smoothing_compare.py

最优插值权重：(λ_uni, λ_bi, λ_tri) = (0.10, 0.70, 0.20)，和为 1.00。

结论

  • MLE 在测试集上必然出现未见 trigram，困惑度直接变成 inf——这不是数值问题，而是模型不可用。
  • 拉普拉斯把已见事件压得太狠（18.44），加 k 降到 0.01 时最好（8.86）；再降到 0.001 反而回升（11.06），说明"少挪一点"存在最优点。
  • 插值（7.28）比最优 add-k 再低 17.8%，与书 §3.6.3 的判断一致：混合不同阶比单阶加 k 更稳。
  • 愚蠢回退的数字最小，但它不归一化，不能当概率解释；这也解释书里为什么把它叫"愚蠢"。

反思

我原本以为"平滑越轻越好"，实测 k=0.001 反而比 k=0.01 差：过度相信计数会让模型对少量未见组合重新变得过严。另一个意外是插值权重里 unigram 只有 0.10，bigram 占 0.70，说明这份语料上低阶信息几乎被 bigram 吸收。下次应把 dev 再切一半做"权重稳定性"检验，避免 λ 只对一份开发集过拟合。
