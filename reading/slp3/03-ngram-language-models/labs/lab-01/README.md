# lab-01：n 阶与训练规模对困惑度的影响

## 目的

对应 `actions.md` 第 1 条：亲手训练 1–4 元语言模型，观察"上下文变长"与"数据变多"分别把测试困惑度推向哪边。

## 语料与方法

- 语料：`../shared_corpus.py` 用固定种子（seed=7）生成 320 句模板句 + 8 句手写异常句，去重后剩 248 句（生成器会重复），再按 70/15/15 切成训练/开发/测试；`build_corpus` 用集合断言确认三个 split 两两无重叠。
- 词表：训练集中频次 ≥2 的词 + `<s>`、`</s>`、`<unk>`，共 68 个；测试集 OOV 映射为 `<unk>`（实测 OOV 率 1.26%）。
- 概率：所有阶统一用 add-k（k=0.1），保证各阶可比；困惑度按 `</s>` 计入、`<s>` 不计入的方式逐词归一。
- 采样：用 k=1e-4 的近似 MLE 分布，每阶生成 5 句（k=0.1 会让高阶模型退化成均匀噪声）。

## 运行

```bash
python3 ngram_perplexity.py
```

无第三方依赖（仅标准库 + matplotlib）。

## 产物

| 文件 | 内容 |
|---|---|
| `out/metrics.csv` | 12 行：4 个阶数（全量训练）+ 2 阶 × 4 个训练比例（训练比例 100% 与全量行重复） |
| `out/ppl_by_n.png` | 测试困惑度随 n 变化（对数纵轴） |
| `out/ppl_vs_train_size.png` | 2-gram / 3-gram 的困惑度随训练 token 数变化 |
| `out/samples.json` | 5 个测试句的 logprob、概率、句级困惑度 |
| `out/samples_generated.txt` | 每阶 5 句采样结果 |

## 关键结果（实测）

| 模型 | 测试困惑度 |
|---|---|
| 1-gram | 46.06 |
| 2-gram | **6.68** |
| 3-gram | 9.92 |
| 4-gram | 13.26 |

训练量从 25% 增到 100%：2-gram 从 11.57 降到 6.68（−42.3%），3-gram 从 18.12 降到 9.92（−45.3%）。

采样示例（`out/samples_generated.txt`）：

- 1-gram：`ham lunch what here know me and know near the </s>`
- 3-gram：`do you know a good place for a table at noon </s>`
- 4-gram：`what time does the menu open tomorrow </s>`

## 结论

- 在约 1.4k 训练 token（1439）的规模上，**2-gram 最优**；3/4-gram 的额外上下文不足以抵消 add-k 对未见上下文的惩罚，困惑度反而上升。这正好复现书 §3.5 的"高阶更像训练集、但泛化更差"。
- 3-gram 对数据量的相对敏感度高于 2-gram（45.3% vs 42.3%），支持"阶数越高越吃数据"的判断。
- 采样结果与书 §3.4/§3.5 一致：低阶是词袋噪声，3/4-gram 开始吐出训练语料里的完整短语。

## 反思

第一次切分时我没有去重，模板生成了大量完全相同的句子，训练集与测试集出现了重叠，断言直接失败——这正是书 §3.2 说的数据污染。去重后困惑度整体上升（2-gram 4.55→6.68），说明之前那组"更好看"的数字有一部分来自泄漏。另一个意外是"n 越大越好"并不成立：平滑把大量概率质量摊给未见上下文，高阶优势被抹平。下次应固定 k 后分别报告"已见/未见上下文"两类位置的困惑度，把上下文收益与平滑惩罚拆开。
