Lab 02 · 玩具 RAG + 问答评估

  • 对应行动：actions.md 第 3 条（⇄ book-notes §11.4–§11.6）
  • 脚本：toy_rag_eval.py
  • 运行：cd labs/lab-02 && python3 toy_rag_eval.py
  • 产物：out/per_question.csv、out/metrics.csv、out/summary.json、out/rag_compare.png

设置（这是模拟，不是真实 LLM）

  • 20 条事实型问题，每题配一段含答案的短文（魔笛首演年份、卢浮宫所在城市……）。
  • 另加 5 条同实体、错误事实的干扰段落，例如把《魔笛》首演说成 1786 年、把卢浮宫说成在里昂。它们模拟「检索到了看似相关但内容错误的来源」。
  • 检索：BM25（k1=1.5, b=0.75）取 top-1。
  • 阅读器：模板抽取器，直接取被检索段落记录里的答案字段，并附上该段落 id 作为引用。它不会推理，只会抄，因此本实验能把「检索错误」与「阅读错误」分开。
  • 三个条件：
  1. closed_book：假设参数里只记住 12/20 条，其余按同类型答案池编造，且不给引用；
  2. open_book_top1：检索 top-1 → 阅读器抽答案 + 引用；
  3. open_book_oracle：直接给金标准段落 → 同一个阅读器（隔离检索错误）。

检索 Recall@1 = 0.85；开卷失败题：f02（卢浮宫→里昂）、f11（物种起源→华莱士）、f13（珠峰→中印边界），且这 3 题全部是「引用了错误来源」。

结论

  1. 开卷不是无条件更好：命中率从 0.60 升到 0.85，但剩下 0.15 的失败换了一种形态——从「没根据」变成「有根据但根据是错的」。后一种对用户更危险，因为引用看起来可信。
  2. 引用率 ≠ 引用正确率：开卷条件引用率 100%，引用正确率只有 85%。只报前者会把这类失败完全掩盖。
  3. F1 会抬高闭卷成绩：闭卷命中率 0.60，F1 却有 0.777，因为错误答案与正确答案共享「年」「公里」一类词元。短事实题应同时报 EM。
  4. oracle 条件把所有损失归给检索：给对段落时全部答对，说明本实验的阅读器是完美的，85% 与 100% 之间的 15 个点全是检索造成。真实系统里阅读器也会错，那时需要第三个条件（给错段落但允许说「不知道」）来分离。

反思

我原来把「加 RAG」默认当成准确率提升。这个实验让我看到更准确的说法是：RAG 把错误从「无据的自信」迁移成「有据的自信」，而后者更难被用户识别。真正该盯的指标不是最终的 EM，而是「引用是否支持答案」——它才是 RAG 独有的失效面。另外，我一开始把 open_book_failures 写成空列表，是因为 build_corpus 里把问题字段当成了答案；这类「字段顺序错」的 bug 在真实流水线里同样常见，评测脚本必须先打印几条样本人工看一眼。

已知局限

  • 闭卷的「记忆」是硬编码集合，不是真实模型的参数记忆，只能说明三类损失可以分开计量。
  • 阅读器不做改写，答案字符串与标准答案同源，因此 EM 偏乐观。
  • 干扰段落是人工构造的，比真实检索错误更「干净」。
