Lab 03 · 复现排序评价（AP / 11 点插值）

  • 对应行动：actions.md 第 2 条（⇄ book-notes §11.2）
  • 脚本：pr_metrics.py
  • 运行：cd labs/lab-03 && python3 pr_metrics.py
  • 产物：out/per_rank.csv、out/interpolated.csv、out/summary.json、out/pr_curve.png、out/interpolated_curve.png

设置

判定序列直接取书图 11.7 的 judgment 列（25 篇文档、9 篇相关）：

R N R N R R N R N N R N N N R N N R N N N N N N R

计算三样东西：

  1. 每个排名处的 Precision@k 与 Recall@k；
  2. AP（只在相关文档命中的位置取精确率，再除以相关文档总数）；
  3. 11 点插值精确率（0.0–1.0，步长 0.1；每点取「该召回水平及更高处」的最大精确率）。

结果（实跑输出）

AP = 0.5972（书 §11.2 报 0.6）
11 点插值 max|diff| vs 书表 = 0.010
插值表: [1.0, 1.0, 0.667, 0.667, 0.667, 0.625, 0.545, 0.467, 0.444, 0.36, 0.36]
书表:   [1.0, 1.0, 0.66,  0.66,  0.66,  0.63,  0.55,  0.47,  0.44,  0.36, 0.36]

结论

  1. AP 可复现：0.5972 与书上的 0.6 只差舍入。单个查询的 AP 就是 MAP（MAP 是对多个 AP 再平均）。
  2. 11 点表逐点吻合：所有点误差 ≤0.01，说明「取右侧最大」这条规则就是书上表格的实际算法，没有隐藏步骤。
  3. 插值确实偏乐观：在召回 0.5 处，实测精确率只有 0.36–0.545，插值给出 0.625（把更靠后、更稀疏位置的高精确率搬了过来）。比较系统时要记住这是「对系统有利的推定」。
  4. AP 与 PR 曲线互补：曲线看形状（左偏还是右偏），AP 给单一数字。只看 AP 会丢掉「系统在前几位是否干净」这一信息。

反思

我原来以为插值只是「把点连起来」，实跑后才明白它是取右侧上确界——等于假设系统在被截断的更深处一定还有好结果。这个假设对排序系统几乎总是成立的（后面的相关文档本来就在那里），但它会掩盖「前三位很差」的问题。以后读论文里的 11 点曲线，我会同时看原始点。另一个收获是：把书上的表格当作单元测试来用，能很快发现自己对定义的理解偏差——我第一次把 AP 的分母写成 25，结果只有 0.215，立刻定位到「分母是相关文档数不是文档总数」。
