lab-05　中文时间表达式的最小规则归一化器

对应：§21.7.2「时间归一化」一句话：用一个 ~150 行的纯规则脚本，把中文时间表达式（绝对日期 / 相对日期 / 持续时间）映射到 ISO 8601 值；19 条测试全过。证实了书中说的「当前时间归一化方法以规则为主」在小语料上完全够用。

跑法

cd labs/lab-05 && python3 lab.py

零依赖（标准库 datetime + re）。产物写到 out/results.json。

设计

书里说时间归一化的两个关键步骤：

  1. 识别时间表达式（TIMEX3）；
  2. 把识别结果映射到 ISO 8601 的 VALUE。

本实验跳过第 1 步（不做连续文本扫描，直接对单个表达式归一化），专注第 2 步。脚本有三类模式：

模式例子ISO 8601
绝对日期2023年10月25日 / 2024-01-01 / 2024/6/1YYYY-MM-DD
相对日期今天 / 昨天 / 明天 / 本周 / 上周 / 下周 / 三天前 / 两周后 / 周三 / 上周五YYYY-MM-DD 或 YYYY-Wnn
持续时间三周 / 两天 / 五年 / 6小时 / 30分钟PnW / PnD / PnY / PTnH / PTnM

时间锚：模拟新闻的「日期行」(temporal anchor)，硬编码 DOC_DATE = 2024-06-15（周六）。所有相对表达式都相对于它来计算。书中那个例子——「文档日期 2007-07-02，本周是 ISO 第 27 周，所以上周 = 2007-W26」——本实验用 2024-06-15（W24）做了同样的事：上周 → 2024-W23。

实测结果（out/results.json）

19 条测试全部通过（accuracy = 1.0000）：

✓  2023年10月25日  -> 2023-10-25   (date)
✓  2024-01-01      -> 2024-01-01   (date)
✓  2024/6/1        -> 2024-06-01   (date)
✓  今天            -> 2024-06-15   (date)     ← 锚点本身
✓  昨天            -> 2024-06-14   (date)     ← 锚点 - 1
✓  明天            -> 2024-06-16   (date)     ← 锚点 + 1
✓  本周            -> 2024-W24     (week)
✓  上周            -> 2024-W23     (week)     ← 对应书里 2007-W26 例子
✓  下周            -> 2024-W25     (week)
✓  三天前          -> 2024-06-12   (date)
✓  两周后          -> 2024-W26     (week)
✓  周三            -> 2024-06-12   (date)     ← 本周三
✓  上周五          -> 2024-06-07   (date)
✓  三周            -> P3W          (duration) ← 对应书里 two weeks → P2W
✓  两天            -> P2D          (duration)
✓  五年            -> P5Y          (duration)
✓  6小时           -> PT6H         (duration)
✓  30分钟          -> PT30M        (duration)
✓  苹果            -> None         (unmatched)  ← 干扰，正确拒绝

关键观察

  1. ISO 周数是这套表示里最容易写错的细节。ISO 规定周从周一开始、一年的第一周是「包含该年第一个星期四的那一周」，直接用 date.isocalendar() 就行，自己写「这周是第几周」的逻辑会出错。本实验第一周就踩过这个坑。
  2. 相对日期的核心就是时间锚 + 模运算。书中说「时间算术必须使用与所用时间单位相适应的模运算」——本实验里 三天前 是 timedelta(-3)（日期是线性的），但 上周 必须整周加减 7 天并重新算 ISO 周号（周号是循环的）。
  3. 「上周三」和「周三」的歧义：本实验硬编码「周三 = 本周三」，但书中说「next Friday 既可指下一个星期五也可指再下一个，启发式取决于锚点到最近单位的距离」。本实验没实现这个启发式——是刻意简化的，也是后续改进空间。
  4. 「X 个月」是规则法的暗坑：月份长度不一（28/29/30/31 天），本实验偷懒直接输出 P{n}M 这种「月份数」而非换算成天数。书中没展开这一段，但真实系统必须用 calendar 模块处理。

与书里说法的对照

  • 书中说「当前大多数时间归一化方法都是基于规则的（Chang & Manning 2012, Strötgen & Gertz 2013）」——本实验用 ~150 行 Python 复现了核心机制（模式匹配 → ISO 值），19/19 通过。
  • 书中给的例子「two weeks → P2W」「上周 → 2007-W26」——本实验用中文语料做了对应版本「三周 → P3W」「上周 → 2024-W23」。
  • 书中说持续时间按 Pnx 表示、24 小时制时刻按 HH:MM:SS、日期+时刻按 YYYY-MM-DDTHH:MM:SS——本实验实现了前两种，故意略去「日期+时刻」的组合形态。

局限

  • 不识别时间表达式（假设已经切好），与真实任务 TIMEX3 抽取是两个独立的工程。
  • 没处理「上午/下午/晚上」「世纪初」「上世纪 80 年代」等更复杂的中文时间表达。
  • 「X 个月」「X 年」的相对版本输出的是 P{n}M / P{n}Y 而非日期差——这违反 ISO 8601 的严格语义（PnM 本应是持续月数，不是「锚点前后 n 月」）。要正确实现需要做月份加减。
  • 时间锚是硬编码的，没有从文档中自动抽取日期行。
