# lab-01　Hearst 式中文模式：类型约束与正则精修的精度/召回权衡

**对应**：§21.2.1「使用模式抽取关系」
**一句话**：同一批种子句，只改两处（加实体类型约束、给「等」补终止符前瞻），F1 从 0.29 抬到 1.00。这说明模式法的短板往往不在「模式不够多」，而在两个更便宜的开关上。

## 跑法

```bash
cd labs/lab-01 && python3 lab.py
```

零依赖（matplotlib 可选，缺了只跳过画图）。产物写到 `out/`。

## 三种配置

| 配置 | 正则 | 类型约束 | 设计意图 |
|---|---|---|---|
| A_naive | 宽松：「等」用贪婪匹配 | 否 | 模拟「先写几条正则就上」的基线 |
| B_naive_plus_type | 同 A | 是 | 只加一条「两端实体类型必须相同」的约束 |
| C_refined_plus_type | 「等」加终止符前瞻（`了/在/随/可/富/支/适/本` 等） | 是 | 再修掉贪婪吞词 |

## 实测结果（`out/metrics.json`）

| 配置 | P | R | F1 | 预测对数 |
|---|---|---|---|---|
| A_naive | 0.2000 | 0.5000 | 0.2857 | 20 |
| B_naive_plus_type | 1.0000 | 0.5000 | 0.6667 | 4 |
| C_refined_plus_type | 1.0000 | 1.0000 | 1.0000 | 8 |

- B 相对 A：精度 +0.80，召回 +0.00。**类型约束只买精度，一点召回也不给**——被剪掉的 16 条里既有噪声也有真信号（如「石花菜等红藻可用于…」整条被贪婪匹配毁掉）。
- C 相对 B：精度 +0.00，召回 +0.50。**召回是正则质量买回来的，不是靠加模式数量**。

## 关键观察

1. **「等」是中文 Hearst 模式里最脏的一个字**。它既是列举标记（`A 等 B` = A 是 B 的一例），又是实义动词（`等了三小时`）。贪婪匹配会把整个动词短语当成上位词（`紫菜 → 红藻富含碘元素`），这是 A 配置精度崩塌的主因。
2. **类型约束是暴力但有效的精度开关**。它不看句法，只看两端实体是否同类型；代价是任何一端不在词典里就整条丢弃，所以对未登录实体极不友好。
3. **两者叠加才是完整方案**：先修正则（保证抽到的东西形态对），再加类型约束（保证语义类对）。顺序反了会误判——B 配置让人误以为「模式法召回只有 0.5 是正常的」。

## 与书里说法的对照

- 书中说模式法「准确率高、召回率低，且构建模式工作量大」——本实验证实了**前半句需要限定条件**：准确率高是「加了类型约束 + 正则写对」之后的事，朴素正则的精度只有 0.2。
- 书中说现代模式方法「加入命名实体约束对其加以扩展」——B 配置就是这个扩展的最小复现，且量出了它的代价（召回不动、覆盖变窄）。

## 局限

- 词典只有 12 个词，等价于「完美 NER」；真实系统的 NER 错误会同时污染两端。
- 语料 20 句、全为单句模板，没有跨句共指，也没有「等」作连词的更复杂用法。
- 未做模式自动归纳（那是 §21.2.3 自举的事，见 lab-03）。
